# RSC 个人仓微信小程序

小程序当前处于 V1.0 生产迁移期。微信手机号授权、短信验证码、可撤销设备会话和
只读查询框架、正式库存账本状态和个人仓元数据读取可复用；盘点、工单物料、需求、
审批和履约写接口尚未完成。

## 当前安全状态

- 正式客户端不提供密码登录、密码修改或临时密码开户。
- 正式认证响应以 `person_id`、`name`、`role_codes` 和组织信息为客户端身份边界；
  小程序不依赖历史 `user_id`、单值 `role` 或明文手机号字段判断登录和路由。
- 仅接受 `admin`、`provincial_manager` 和 `technician` 进入运营客户端；
  `star_headquarters_approver` 只允许进入未来独立审批页。`auditor`、
  `warehouse_manager` 和未知角色一律失败关闭。
- 发布导航只注册登录、正式工作台和“我的”。v0.9 工作台、库存、Transfer 历史、
  旧盘点、旧工单物料、OAM 申请和旧媒体页面均未注册，也不能通过深链进入。
- 请求守卫对 v0.9 业务路径的 GET、HEAD、OPTIONS 和写请求一律阻断；旧余额和旧状态
  不得作为正式库存、个人仓、盘点或 V1 十条状态轴的读取来源。API 路径必须是规范站内
  相对路径；fragment、编码路径分隔符、dot-segment、反斜杠和绝对 URL 均在传输前拒绝。
- 工作台和“我的”先读取 `/auth/me` 与 `/access/context`，身份、人员 ID 和授权版本
  必须一致。进入库存能力必须同时满足
  `access_mode=active`、有效正整数 `authorization_version` 和精确的 `inventory/read`
  权限；`restricted_handover`、缺权限或缺授权版本均失败关闭。
- 通过门禁后，工作台只读 `/v1/inventory/summary`，“我的”只读
  `/v1/inventory/personal/me`。客户端逐字段验证 `schema_version`、正式枚举、UUID、账本
  游标、人员/库位/保管关系和三位小数字符串；字段缺失、未知枚举、游标倒挂或身份不一致
  一律失败关闭。
- 后端 `0010` 已提供正式盘点与期初证据表，并有不挂路由的内部启动服务固定 scope、控制快照、
  零正式账本快照、冻结和首轮任务；`0011`–`0015` 及内部首轮实盘服务已能封存完整范围实物、显式空
  范围、逐件 SN、待核实观察和整轮提交，并以标识类型、显式封轮 completion、不可变审计和完整
  证据链防止别名重复与重放篡改，但没有挂载正式 API，待核实处理、复盘、双复核和终结
  仍未完成。启动任务、首轮已提交、表存在或单笔低层 `opening` 流水都不能证明首次盘点已经由
  区域负责人和蔚来总部管理员完整复核。
  因此服务端明确返回“期初未建立”，小程序隐藏所有余额。它不会显示假零值，也不会把不同
  SKU 或计量单位的数量直接相加；个人仓此时只接受库位与保管元数据，拒绝未复核的账户明细行。
- 开发版只连接本机 `127.0.0.1`。试用版/正式版默认没有服务地址，所有网络请求会在
  本地失败关闭；发布负责人必须在 `utils/release-config.js` 填入已审核的 HTTPS API
  和 PC Origin，代码不再内置任何生产域名。
- 所有 `/auth` 非 GET/HEAD/OPTIONS 请求在首次逻辑调用前均由请求层生成独立
  `X-Request-ID` 和至少 144 bit CSPRNG 熵的 `Idempotency-Key`，覆盖短信发送、短信登录、
  微信登录、刷新、退出和未来管理员强制下线。键只允许固定 `wxidem-` 前缀和随机十六进制，
  不拼接账号、手机号、验证码、令牌、设备或会话标识；安全的调用方键会原样复用，冲突或
  非法键失败关闭。
- 客户端只合并同一进程内的并发刷新；单个 in-flight 刷新固定一组请求坐标。本地认证
  变更统一使用不含 token、用户、设备、手机号或幂等键的三种持久哨兵：刷新
  `pending-v1`、显式登录 `explicit-login-pending-v1` 和退出 `logout-pending-v1`。
  进程重启发现任何遗留或未知哨兵时，必须清除全部会话字段并重新登录。
- 刷新哨兵在生成刷新幂等键前持久化。短信/微信登录哨兵在进入 `wx.request`
  前持久化；确定的客户端 HTTP 拒绝可撤销哨兵并恢复原完整会话，网络失败、
  超时或非确定服务端错误保留哨兵并失败关闭。新会话四个字段全部写入且
  回读一致后才清哨兵；退出则先落哨兵，确认所有凭据字段均已删除后才清哨兵。
- 短信或微信显式登录响应到达时，会先使同进程内的旧刷新代次失效，等待该请求收口后
  再写入新会话。旧刷新的迟到成功或失败均不得覆盖或清除新的显式登录会话。
- 普通业务写不会被请求层误加认证幂等键；各业务域仍必须按正式状态机独立提供幂等坐标。
- 小程序和 Web Crypto 均不可用时认证写请求失败关闭，不降级使用时间戳或
  `Math.random()`。

## 本地导入与验证

1. 用微信开发者工具导入本目录。
2. 在开发环境启动本地 API，并确认开发版使用 `http://127.0.0.1:8000/api`。
3. 运行生产守卫测试：

```bash
node --test miniprogram/tests/*.test.js
```

4. 检查所有 JavaScript 语法和 JSON 配置后，再做开发者工具预览。

本仓库中的 AppID、合法域名或历史部署线索都不构成发布授权。试用/正式构建前必须由
小程序管理员确认目标 AppID、HTTPS 合法域名、隐私协议、微信手机号能力、AppSecret
服务端配置和发布账号，并完成真机、弱网、退出/强制下线及越权验收。
