## 真实执行的本地流程

恢复既有合成应用备份，在当前正式 schema 上创建新的签名物料采集、授权、审核和发布；
使用现有真实 JWT/会话与来源配置命令建立新目录及规则授权。仅源查询和文件存储替换为
合成传输，HMAC 验证、受限 Edge 接收、暂存完成、准备、审核发布和数据库守卫都实际执行。
未关闭触发器或改写原发布记录，未调用业务网络或真实供应商。

目录明确将 W-A、W-B 两仓绑定到目标区域，W-A 包含 P-A 与 P-ZERO。该绑定是合成夹具
明确提供的目录事实，不从数据行、仓库名称或地理名称推断范围。

| 顺序 | 新发布及实际读取结果 |
| --- | --- |
| 多仓全量 | 4 条 origin、2 个省级物料/成色汇总行；拆回 W-A/new = 5、W-B/new = 7、W-B/damaged = 4。原锁定量 1 和 2 单独保留，不从控制总量自行扣除 |
| 增量 | 第一条从 2 改为 6，删除指定 damaged 来源，其余保持；拆回 W-A/new = 9、W-B/new = 7。3 条 origin 同时引用第 1、2 次采集，未变来源指针保留 |
| 两仓全空 | 0 行、0 origin，两个目标仓仍在覆盖清单，每仓保留成功的第 1 页/0 总数；不伪造物料证明 |
| 来源再出现 | 重新发布最初的 4 条来源；原多仓、增量和零仓批次均可准确读取，关闭/替换关系不覆盖旧结果 |

每次新增发布后，重新读取之前批次。除本次数据库观察坐标和其派生内容摘要外，历史输出
全部字段保持一致；最终验证器也逐份核对 JSON 内容摘要、准确批次坐标及手工预期数量。

## 撤权与库存边界

- 通过正式映射命令撤销规则授权：4 个旧批次仍可读取；撤权后新增签名采集，确认新准备
  尚未发布，其发布预检被
  `mapping_unavailable` 拒绝。
- 随后通过正式来源配置命令撤销来源授权：4 个旧批次仍可读取；再次新采集并确认未发布，
  其发布预检被
  `source_authority_missing` 拒绝。旧历史读取不会重新授予来源权限。
- 每次只读采集前后核对其 27 张依赖表摘要；发布与撤权产生其各自正式事实，读取不增加事实。
  从首次建立新来源到全部撤权结束，`inventory_transactions`、`inventory_movements`、
  `stock_balances`、`stock_accounts`、`stock_locations`、`inventory_ledger_heads` 六表摘要一致。
- 两个临时实例通过既有 helper 新建，只监听私有 Unix socket；均已核对服务器退出 0、停机日志、
  postmaster PID 文件和 socket 消失。未重新启动旧目录，不是 GitHub 专用发布门禁。
