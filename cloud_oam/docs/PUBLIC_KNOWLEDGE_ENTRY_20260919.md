# 公开备件查询与个人仓入口变更

## 当前需求与实现

用户于 2026-09-19 要求网站和小程序首页展示“交流备件知识大全”，不展示登录界面。
随后明确个人仓地址为 `rscwz.cn/xx`，因此本轮实现的是同域名下的二级路径，取代此前的
二级域名设想：

用户随后要求网站首页保留“星星后台管理”按钮。该按钮位于页首，直接跳转 `/xx`；
首页本身仍是公开知识查询，不嵌入登录表单。

| 地址/客户端 | 行为 |
|---|---|
| `https://rscwz.cn/` | 公开备件查询；保留“星星后台管理”链接，不加载个人仓认证客户端 |
| `https://rscwz.cn/xx` | 308 跳转到 `/xx/`，显示原个人仓登录页 |
| `https://rscwz.cn/xx/…` | 原个人仓路由，保留服务端身份、权限与业务写入门禁 |
| `/api/…` | 保持原有后端路径与认证机制；没有开放匿名库存查询 |
| 小程序 | 仅注册公开知识页；原业务页源码保留，但从公开页面注册和上传包排除 |

此需求覆盖旧基线中网站/小程序首先进入登录页的安排。库存、通知、验收、入账、对账、
角色和权限要求均继续遵循 V1.0。这里的目录是备件知识快照，与库存主数据、库存余额和
通知事实没有同步关系。

网页提供编码、名称、型号和说明的多关键词查询、分类筛选、分页、来源表名/行号及版本日期。
小程序使用相同的静态目录和查询规则，无需请求业务 API 或进行微信登录。

## 构建与路由

在 `cloud_oam/frontend` 内：

```sh
pnpm dev                    # 公开知识页
pnpm dev:warehouse          # 使用 /xx/ 的个人仓开发入口
pnpm build                  # dist：公开构建
pnpm build:warehouse        # dist-warehouse：个人仓构建
pnpm verify:release         # 网页目录发布检查；pending 或构建过期时失败
```

两套入口分别编译，不依赖运行时登录状态或审核身份切换。Dockerfile 将目录分别复制到
`/srv/public` 和 `/srv/warehouse`，并强制运行目录发布检查；没有绕过空目录的构建参数。
Vite 在公开构建中输出与源码一致的 `knowledge-catalog.json`，发布检查拒绝构建后才变更的目录。
该检查验证字段、来源坐标、核对时间、导出摘要和非空记录；它不替代与原表的人工核对。

Caddy 对 `/xx/*` 去除前缀后提供个人仓资源，其余页面提供
公开资源；React Router 使用 `/xx` basename。该配置采用
[Caddy 官方 handle_path 规则](https://caddyserver.com/docs/caddyfile/directives/handle_path)。

保留 `APP_DOMAIN` 配置，目标部署应设置为 `rscwz.cn`。没有新增 `WAREHOUSE_DOMAIN`，不需要
为了本轮要求变更数据库或 Cookie 的 `/api` 路径。当前代码尚未部署到该域名。

根目录旧 Service Worker 更新后删除旧个人仓首页缓存，且不再拦截 fetch；个人仓的 worker、
manifest 和启动 URL 都限定到 `/xx/`，缓存键单独命名。旧离线安装实例须至少联网更新一次，
才能接收新的首页与缓存退休脚本。

公开与个人仓文档、worker 和静态资源采用 `Cache-Control: no-cache`，更新时重新验证；API
保留后端的缓存策略。`/assets/*`、`/brand/*` 等静态资源缺失时直接返回 404，不能回退为 SPA
HTML。私有 worker v4 只处理同源 `/xx/` 的 GET；API 不拦截，断网时只有文档导航可回退私有
首页，JS 等资源必须命中当前缓存的精确条目。服务器明确返回的 404/5xx 保持原响应。
这不代表个人仓已支持完整离线使用：当前 shell 预缓存不包含所有打包 JS/CSS。

本地可用已安装的 Caddy 验证真实路由，后端使用本地 401/503 stub，绝不连接生产认证服务：

```sh
python3 cloud_oam/scripts/preview_public_entry.py --caddy /path/to/caddy
# 自动检查后停止，使用临时回环端口，不影响已运行的预览：
python3 cloud_oam/scripts/preview_public_entry.py --caddy /path/to/caddy --port 0 --check
```

预览地址为 `http://127.0.0.1:18085/`，进程仅绑定本机回环地址。Caddy 配置/数据目录临时隔离。

在仓库根目录检查双端发布目录：

```sh
node cloud_oam/scripts/verify_public_entry.mjs --release
```

默认不带 `--release` 的 Client gate 允许内容明确标为 pending 的开发构建，输出标记为
`mode=development`；小程序上传前必须通过上面的发布检查，并完成开发者工具与真机验证。
当前两个发布命令均以 `PUBLIC_CATALOG_NOT_READY`、退出码 1 拒绝放行，不能将该预期拒绝
写成真实目录验收通过。
