## 新行为

7.65 已约束控制批次在新任务插入及提交时仍有效，但旧 0052 的角色有效期比较使用事务
开始时间与任务 cutoff，不能单独证明角色在提交实时时刻仍有效。本批新增前向迁移
`20261105_0126`，不修改前 125 个迁移文件。

`stocktake_tasks.opening_authorization_version` 保存服务端最终核验的操作者授权版本。
新 PostgreSQL 期初任务必须有正整数版本；版本不由请求体输入，必须与当前用户完全一致。
字段创建后不可修改，旧任务保持 NULL，代表当时没有该证据，不反推、不补写当前版本。
非期初任务的该字段必须为空。

新内部触发器先沿用人员权限图、控制发布的锁顺序，再用 PostgreSQL `clock_timestamp()`
检查账号、人员、验证身份、准确区域、全部有效角色和区域祖先范围内的拒绝规则。
检查结束再验证期间没有跨过授权时间边界，包含即将生效的定时拒绝授权。
BEFORE INSERT 与延迟约束触发器分别覆盖落任务及提交时刻；角色到期或拒绝规则生效时，
任务、范围、冻结、初盘、快照、状态事件、审计、outbox 和相关账本投影整笔回滚。

数据库只增加两项内部执行函数和三个 ALWAYS 触发器，没有新增运行角色执行权限、
私表查询权限或库存写入口。生产启动校验固定新函数正文、签名、属性和触发器配置；
迁移校验同时检查字段类型、无默认值、可空性与准确 CHECK。已有非空授权证据时拒绝
降级，防止删除证据；正常历史回读和任务后续状态更新不执行新的当前创建人授权检查。

当前授权拒绝携带固定数据库诊断标记。服务层及 HTTP 提交层只将该标记对应的拒绝转为
`opening_authorization_changed` / 403，响应禁止缓存且不含 SQL、驱动详情或身份原始数据。
无关数据库异常继续作为未确认结果处理，不能凭错误文字猜测已经回滚或自动重发。
