# 8.07 日终审核持久化与数据库守卫候选

本批在全新自有 PostgreSQL 16 中接入 [8.06 审核核心](DAILY_RECONCILIATION_REVIEW_20260921.md)，
验证日终解释、退回补证、独立审核与原请求恢复。实现位于
`artifacts/daily-review-persistence-20260921/`，当前没有注册 0132 迁移或 HTTP 写接口。
正式 Alembic HEAD 仍为 **20261110_0131**；不能把本批合成库中的提交视为生产数据库已审核。

## 已实现的持久化候选

- 沿用 `reconciliation_runs`、`reconciliation_items`；新增日终绑定、不可变事件及消费记录。
  一份截止仅对应一份运行；版本连续，操作者的幂等键和请求 ID 在不同运行间也唯一。
- API 角色从窄只读视图取得截止内容，验证签名 JWT、当前会话、人员状态与精确区域授权。
  原始 OAM 账本和私有截止档案不进入请求体；不传入 owner DSN。
- 数据库自行计算解释和审核状态，检查截止摘要、来源数量、前一事件、解释版本和附件元数据。
  修改数量、重算请求摘要或伪造“已审核”状态都不能替代有效的领域动作。
- 区域只解释自己的范围；总部独立审核。解释过该对账的同一人员，即使同时拥有总部和区域
  两种角色，也不能审核。重复或歧义授权不作为有效授权。
- 每项解释保留原文字、附件观察和历史人员；定向退回不会清空其他项目。
  已批准状态只把对账差异标为已处理，不改原数量、不产生库存流水。
- 先锁会话与权限图，再锁精确截止/运行和排序后的文件，最后锁审计链头。
  提交前再按数据库当前时间核验会话、权限期限、附件及完整投影。
- 命令、投影、审计与消费记录必须在同一事务完成；缺少消费记录不能提交。
  只有审核状态实际变化时新增状态转换事件；部分解释仍处于相同状态时不伪造一次转换。
- 原始回执按原请求恢复，包含当时的版本和状态。后续审核不会把先前的解释回执改成最新结果。
- 两只 0026 通用投影守卫只新增已绑定日终对象的校验分支，原期初分支正文逐字节保留。
  空候选回退恢复原目录；已有日终历史时拒绝回退，不删除数据。
