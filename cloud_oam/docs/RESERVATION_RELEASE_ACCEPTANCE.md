# 库存占用释放验收

本批按正式生产版 V1.0，在分配与占用之后增加独立释放事实、补偿流水和 Web 页面。
开发分支为 `codex/production-readiness-gates`，迁移唯一 head 为 `20260910_0070`。
备案与开发并行推进；本记录不代表已部署或已完成整个 V1.0。

## 已实现的行为

- 按原占用单查询可释放数量、位置和精确 SN；同时检查需求范围、库存读取与过账权限。
- 数量按最多三位小数处理，释放不得超过本笔余量；SN 必须来自本笔且尚未释放。
- 释放从原占用账户回到原可用账户，沿用正式库存过账、投影回读、审计链与事务 Outbox。
- 追加 `stock_reservation_releases` 与 `stock_reservation_release_serials`，不改写原占用及原分配事实。
- 释放不恢复已消耗的分配额度；原分配尚未占用的余量仍可继续占用。
- 请求结果不明时保存原操作记录，暂停其他写入，通过原请求只读查询核验，不自动重发 POST。
- 释放成功后重新读取需求并核验原记录、数量、SN、账户及其他独立状态，才清理恢复记录。

当前仅允许批准后、出库尚未开始的直接释放；已开始出库的需求需要后续履约补偿流程。

需求的占用状态按历史占用总量与释放总量计算：有释放且仍有净占用为 `partially_released`，
全部净占用归零为 `released`。追加事实不一定改变整体状态；状态未变时记录该事实的创建事件，
状态变化时记录需求状态迁移，避免生成“部分释放到部分释放”的虚假状态事件。

## 接口与数据库边界

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/material-requests/{id}/reservation-release-options` | 按需求明细读取原占用余量与 SN |
| `POST /api/v1/material-requests/{id}/reservation-releases` | 原占用、数量、原因、SN 与版本坐标一起提交 |
| `GET /api/v1/material-request-reservation-release-command-status` | 通过原 `X-Request-ID` 只读恢复 |

接口返回 `no-store`。写入需要有效的版本、幂等键和授权；同一键不同内容被拒绝。
历史恢复核验命令、原占用、释放事实、库存事务及移动、SN、审计链和状态事件，不依赖当前库存位置
猜测历史结果。原身份或授权改变、证据缺失、存储故障时保留原恢复记录。

0070 新增五个保护函数与十二个 `ENABLE ALWAYS` 触发器，纳入运行时函数体哈希、所有者、
执行权限、执行身份和目录完整性检查。延迟约束核验占用/释放/命令/流水/审计/事件完整关系。
API 仅可追加，迁移角色在 replica 模式下也不能改写事实；存在释放事实时禁止降回 0069。
历史迁移文件保持原样，升级通过精确匹配既有函数体替换，降级恢复对应历史函数与权限。
