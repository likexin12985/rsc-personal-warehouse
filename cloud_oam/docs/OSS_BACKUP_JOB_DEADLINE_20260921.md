## 已接入的行为

- `backup-entry.sh` 要求明确的 `RSC_BACKUP_TIMEOUT_SECONDS`，为正整数且不超过 86400。
  主机 Python 3.11 以上是显式前提，不能使用开发机虚拟环境路径作为生产解释器。
- 外层监督器给 `backup_steps.sh` 传递同一单调时钟截止点，每阶段计算剩余时间；没有
  为下一阶段重新分配完整预算。截止时间后的取消有独立清理宽限，并非到点即刻完成所有清理。
- 主机私有 TMPDIR 位于 BACKUP_DIR 同一文件系统，所有 job 暂存均在其下。外层在受控
  子进程结束后统一清理，内层 shell 不抢先删除仍可能写入的 job。旧完成包不属于临时目录。
- `lease_sender.py` 每 250 毫秒向远端 stdin 写入存活点；远端必须先收到有效点才启动
  导出，随后连接关闭、无效数据、超过 2 秒无新信号或阶段期限到达均停止受控工作。
  原始二进制 stdout 保持用于导出，监督日志只去 stderr，不输出凭据或命令参数。
- 主机宽限为 6 秒，远端为 1 秒。父进程丢失由原 keeper 管道处理；即便运输进程被
  主机终止，独立会话内的导出仍须依赖存活信号终止。真实容器缓冲、调度和断连时序另需验证。
- 数据库仍只使用备份只读角色、同快照导出、完整目录检查和专属连接断连检查；不增加
  BYPASSRLS、角色成员或写权限。对象 worker 的 SDK、流式目录、校验和恢复代码未改。
- 只有成功 worker 输出且再次通过 SHA256 校验的包才用排他硬链接发布。取消发生在
  已发布之后时，应核验具体完成包；不能把任意非零退出都解释成“没有发布”，或盲目删除文件。

worker 之后损坏文件，并强化实际阶段断言。`entry-retry-checksum` 完成四次远端调用，
