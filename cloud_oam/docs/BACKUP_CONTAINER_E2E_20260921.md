测试 Compose 使用这些工件和正式入口所需挂载，并显式增加隔离夹具：

- DB 由原 `local_pg16_cluster.py` 在容器内新建、绑定子进程与系统 ID，只有私有 Unix socket，
  TCP 关闭；合成 SQL 恢复后运行正式只读备份角色与导出流程。不接外部 DSN，不复启旧库。
- API 是镜像原 Uvicorn 启动命令，`OAM_ENVIRONMENT=test`、`alembic` 模式，真实 `/api/health/ready`
  返回 200/ready，并核对实际数据库用户为 `star_oam_api`。这不是 production 启动、KMS 或身份验收。
- 服务均 `network_mode=none`，无发布端口。worker 保留只读根目录、cap_drop、no-new-privileges、
  init、内存/进程限制；额外的测试 hook 只注入合成 OSS transport 和受控停顿。
  正常数据库导出使用真实 pg_dump；停顿场景才由夹具改为实际 `pg_sleep` 查询。
- 当前两库及前两次创建过的失败样本库，共 4 个新实例均正常停止，数据目录保留。
  私有 Docker 引擎停止、其容器全部清理、共享 containerd 无运行任务，VM 最终 Stopped。

源表摘要使用与 7.99 原证据一致的 `Asia/Shanghai` 会话输出时区；数据库默认 UTC 没有改动。
同时保留原生 UTC 摘要与比较格式记录，避免把同一 timestamptz 的不同文本形式误判为数据改变。

## 已保留的失败与恢复

1. **12405**：8 GiB 临时 VM 在加载 DB 镜像时空间不足，尚未启动服务。保留失败工件后，
   仅把此自有 VM 磁盘扩容至 32 GiB，前后配置证明仅 disk 字段改变；重新创建私有引擎目录。
2. **76891**：夹具的安全解包允许项遗漏 `dependency-source-hashes.json`，服务前即拒绝。
   补上这一确定文件；未放宽任意路径、符号链接或其他成员的检查。
3. **75191**：新容器默认 UTC 与原上海时区证据的文本摘要不同。按原配置设置比较会话后，
   206 张表全部一致，保留两种输出；未修改数据库内容或预期摘要。
4. **56685**：合成 transport 引用了未打包的 `backup_test_support`，测试 hook 在真实网络前
   退出 90。补入未改动的测试模块后重跑；每次失败的实例、引擎和 VM 均已停止。

容量测量的 `dd` 会按设计触发文件大小信号，当前 dash 日志可显示 `File size limit exceeded`；
这不是上述正常备份失败的依据。以准确退出码、完整包、验证回执及恢复结果判断。
