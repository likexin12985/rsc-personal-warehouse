申请入口要求独立的 `report.export` 权限与现有 `inventory.read` 权限，两者均在当前
正式人员/角色图上核对。申请人、授权版本、有效作用域、筛选条件、申请时账本游标及
幂等键固化在任务记录；不得由客户端指定人员范围或提升组织层级。任务只记录已校验
字段，不把 access token、数据库连接、OSS 凭据或整表数据存入参数 JSON。

后台 worker 按任务 ID 领取待执行项，以数据库行锁防止双重生成；执行前重新读取人员
状态、授权版本和权限图。权限已变更或账本游标与申请时不一致时拒绝旧任务，要求重新
申请，不能静默导出新范围/新时点。沿用正式库存读取的期初证明、账本连续性、授权范围
和投影重建校验；无期初或证据矛盾时失败关闭。`.xlsx` 以流式方式生成，限定行数、
单元格长度和总字节数，转义可能触发电子表格公式的文本。私有 OSS 对象写入后核对
大小和 SHA-256，再将 `files` 对象与任务结果绑定；对象写入成功而数据库提交未知时，
通过确定性对象键与 HEAD/hash 精确恢复，不能盲目重复覆盖。

下载由报表专用接口执行：重新校验当前身份、任务申请人及相同范围权限，核对文件状态、
对象 hash 后签发短时下载意图；下载意图与不可变审计同事务记录。`download_count`
表示成功签发的受控下载意图次数，不把预签名 URL 实际传输误报成已下载完成。
首批任务详情与下载仅向申请人本人开放，并再次核对当前权限与原范围；身份停用、范围收缩或文件被隔离时
拒绝下载。文件 URL 不进入公开首页、小程序知识查询或通用日志。

## 必须一同落地的门禁

`0136` 已新增仅针对 `job_type=export` 的运行时任务守卫：申请只能插入具备授权版本、
作用域和游标的 `queued` 行；worker 只能领取 `queued→running` 并写入一次成功或失败
结果；成功行仅可使下载意图计数单调加一。申请人、筛选条件、授权/范围快照和游标
不可变，删除/截断被禁止；API 更新列权限已收窄。`0137` 已扩展私有文件用途和当前
