## 改造范围

- 完整 worker 路径采用私有临时 SQLite 索引；它仅存本任务元数据，不是应用数据库，
  不接收数据库凭据。文件 0600、任务目录 0700，关闭 mmap、固定 2 MiB 页缓存，磁盘页
  数按任务容量限制。目录 ID/存储键唯一性由索引约束校验，按 ID 顺序迭代。
- `files.ndjson` 每次只解码一条记录，记录上限 1 MiB；逐条调用现行纯校验规则。先
  完整检查目录、计数、重复和附件总量，再允许请求对象。末尾损坏不导致提前下载。
- 对象按顺序下载、验长/哈希/原完成凭据、加入 tar 后删除本次临时对象；下载凭据保存
  到磁盘索引。对象 manifest 的 catalog/objects 数组逐条写出，catalog 摘要保留原有
  canonical JSON 数组算法，没有改成不兼容的新协议。
- 恢复时逐条解析原 v1 manifest，限制单记录、嵌套和读取缓冲，拒绝重复键和重复成员；
  用磁盘索引逐项绑定原数据库目录、对象内容和完成凭据。原 manifest 文件原字节保留，
  无需第二次把数组全部载入内存。
- tar 只接受普通成员，扩展头/稀疏头在解析其声明载荷前拒绝。对当前 Python 3.12 的
  顺序读写清理成员缓存；不能只把模式改成 `r|` 就认定内存恒定。流式模式语义参考
  [Python tarfile 官方文档](https://docs.python.org/3/library/tarfile.html#tarfile.open)，
  具体缓存行为以本次安装源码与规模实测为准。
- 索引成功、校验失败、容量不足及初始化失败均关闭连接并清理本次文件，旧备份保持。
  目录/对象数组的旧辅助函数只供历史小夹具使用，完整 worker 已走新流式路径；正式
  接入时应同步收敛内部接口，不能再把旧辅助函数接回任务链。
