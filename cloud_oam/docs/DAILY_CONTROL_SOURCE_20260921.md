## 当前行为

- 请求必须指定 publication ID、准确 hash、来源系统和区域 UUID，不从名称、当前页面或
  全局最新行猜批次。来源和本地库存继续分开；本函数不调整库存、发通知或写对账结果。
- 使用专用 `rsc_control_capture` 角色，在首次 SELECT 前锁定 27 张依赖表，再固定只读
  REPEATABLE READ 快照。检查最小表读取权限、无所有权/角色成员/提权属性，并核对已有
  RLS 的专用完整读取策略，拒绝全部限制性 SELECT/ALL 策略。角色和策略仅在新测试库创建。
- 复用 `prove_control_publication`、`read_inventory_control_preparation` 等实际函数，核对
  发布图、同步批次、逐行来源、暂存快照/批次/记录及审计链。按发布创建时刻复核原来源和
  目录授权范围、采集回执与映射决定，不把自然过期后的当前时刻当成原采集时刻。
- 重新执行既有全量/增量采集重建、规则归一化及原始来源指针重建。逐条核对仓库、库位、
  物料、成色、原数量和锁定量，并核对每个汇总行等于对应来源之和。锁定量单独保留。
- 每个来源引用的已发布物料也复用正式证明函数，验证其接收凭据、版本、政策和审计链。
  返回的数据摘要是完整性证据，不等于密钥生命周期或真实外部业务已经验收。
- 返回全目录的分页覆盖和目标区域的位置清单。公开接口不能直接返回这些内部资料。
  缺页、缺仓或缺行整体拒绝；不根据剩余来源行推导“完整目录”，不把缺失标成零。
- 原始采集时间、原发布时间、原有效期与本次数据库观察时间分别保存。每条 SQL 使用同一
  整项剩余预算；超时不返回部分结果。输出当前操作者授权、当前源授权、仓库映射批准、
  密钥治理、持久化和库存写入标志均为 false。

## 实际证据及边界

最终原生会话 **40933 退出 0**，16 项不累计历史尝试；检查数据库通过既有
`local_pg16_cluster.py` 新建私有 Unix socket，未监听 TCP，未启动历史数据目录。
恢复输入仍是 7.79 固定合成应用备份，摘要
`1746986185c63427c276e911dee4ca3519e6540cb2e8252b3f316e92d9d3a774`。
本次是局部开发验证，不是 GitHub PG16 发布门禁。

| 验证范围 | 实际观察 |
| --- | --- |
| 已发布批次正常读取 | 1 条来源，数量 0；目标仓 W-A 包含 P-A 与无来源行的 P-ZERO；另一地区仓 W-B 保留成功返回 0 行的第一页证据 |
| 精确批次与权限 | 错 publication、hash、来源、区域、来源数量预算和误授 UPDATE 均准确拒绝 |
| 来源完整性故障 | 改 origin 正文/数量、删目录空库位、删 W-B 的空仓页、改源总数、改选定采集回执或映射规则均拒绝 |
| 整项期限 | 合成慢查询超过同一剩余预算时拒绝，随后可重新完整读取 |
| 无业务变更 | 专用读取记录只有 SET / LOCK / SELECT；30 表包括来源证据、库存交易/流水和余额，前后摘要一致 |

故障注入只在新建的合成数据库，由测试所有者短暂关闭目标表的用户触发器、修改一个确定
字段；每次恢复原值和各触发器原始 O/A/R/D 模式后，重新比较全部受检表摘要。它不是迁移
或运行时允许绕过守卫的实现。

失败证据保留：`63746` 因检查夹具误以为余额表有 `id` 退出；修正排序键后，`26512` 的
回执故障选择了未被目标批次引用的旧回执，不能充当拒绝证明。改为按选定采集链精确定位，
`65579` 的原 15 项通过。补充整项期限后最终 16 项通过。四个不同系统标识的实例均已核对
服务器退出、postmaster PID 文件和 Unix socket 消失，空审计目录保留。
