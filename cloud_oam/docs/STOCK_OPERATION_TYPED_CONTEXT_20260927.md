# 库存作业类型化结构：报损持久化前置迁移

日期：2026-09-27。依据正式基线 §1.11、§3.9；候选迁移 `20261121_0142`，
前驱 `20261120_0141`。本页只记录结构及兼容性验证，不是报损业务或上线完成证明。

## 变化与边界

原共用库存作业表强制所有单据都有工单、回收明细、目标仓和运输仓。普通个人库存
报损没有这些事实。0142 按 `return` / `loss_report` 区分单头与明细，使用显式
NULL 条件及复合外键，避免为报损伪造工单，也避免放松既有退回的必填关联。

- 退回仍必须绑定工单、回收明细、接收保管责任、不同的来源/目标/运输位置；
  仅允许旧件或坏件。
- 报损的工单、回收明细和运输关联必须为空，允许新/旧/坏件；明细类型必须匹配单头。
- 旧明细回填 `return`。原审计、库存证明、不可变触发器、权限种子均保留。
- PostgreSQL 和 SQLite 都有独立插入触发器拒绝报损写入。完整冻结、审核、附件、
  幂等恢复及过账证明尚未安装，不能只增加枚举便开放提交；没有新增正式操作权限。
- PostgreSQL 私有触发函数禁止 API、备份和边缘角色执行；启动安全清单绑定其
  函数源 hash、SECURITY DEFINER、search_path 和 ALWAYS 触发器。
- 降级只允许已有退回历史；遇到非退回类型先拒绝，禁止删账。数据库版本和运行
  就绪函数同步升级，函数 hash 不符合预期时整次迁移失败。
- SQLite 表重建保存并原样恢复本表及其他表中引用这两张表的触发器；迁移要求
  开始前关闭该测试连接的外键检查，不在事务中静默切换。
