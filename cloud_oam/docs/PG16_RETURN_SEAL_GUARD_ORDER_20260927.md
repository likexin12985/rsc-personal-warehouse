日期：2026-09-27；父提交 `ac83fd219c9b1e695d3a3485088c2f2e9ad5cf67`。
本修复仅涉及测试辅助函数、真实 PG16 合成夹具、本地验证脚本和本文。
不改变业务服务、数据库函数、权限、正式迁移或库存规则。

## 故障与修复

准确父版本的 GitHub runtime job `108548292469` 在
`pg16_stock_return_recovery_gate.py:76` 失败。封存后故意绕过应用预检，执行
完整迟到退回命令，数据库拒绝为 `0110 return request namespace conflict`；
旧测试却要求只出现 `0101 sealed return request cannot execute`，依赖了
多个延迟约束的触发顺序。并非数据库接受了原请求。

修复对数量和 SN、提交和取消、封存先到和业务先到分别执行三个反例：

1. 显式触发准确 0101 约束，要求该方向的准确 0101 错误文本及 SQLSTATE 23514。
2. 显式触发准确 0110 请求冲突约束，要求准确 0110 错误文本及 SQLSTATE 23514。
3. 启用全部约束，仍要求上述两个已独立证明的准确拒绝之一，不接受任意数据库异常。

共 24 个组合，每次反例单独使用 savepoint，随后回读既有库存、余额、SN、账本
游标、审计链、Outbox、工单及退回/封存记录快照，验证回滚。原来的 SELECT-only
回查、原单恢复、合法提交/取消和整事务回滚验证保留。
