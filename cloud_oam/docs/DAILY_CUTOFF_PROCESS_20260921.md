## 当前实现范围

内部固定操作通过 spawn 启动独占工作进程。三个连接来自服务端配置，使用 NullPool；
请求只传原操作坐标、认证和版本，不能提交库存快照或选择执行代码。凭证在进程内部管道
传递，不写命令行、日志或结果文件。正式 API、配置载入和专用角色仍需接入评审。

父进程从启动前计时，覆盖模块载入、建连、计算和事务；工作进程把剩余预算传入 7.96，
没有重新取得一份完整事务时间。父进程只做有期限的非阻塞读取，即使收到半截回执也不会
卡在 recv_bytes。结束时关闭存活管道、终止并回收本次工作进程；清理另有最多一秒等待，
无法确认结束时明确报告清理未确认，不冒充成功。操作期限不是操作系统的硬实时保证。

工作进程启动后的独立线程监视存活管道与绝对期限，父进程消失时退出。管道由父进程
持有，不持续发送心跳，避免暂停的工作进程让发送端阻塞。无确认结果统一要求原请求
恢复，不自动重试，也不把无法确认 COMMIT 的情况报告为已回滚。

## 实际验证

| 场景 | 可复核结果 |
| --- | --- |
| 正常截止与原请求恢复 | 实际提交一份截止，恢复同一记录；再次恢复不增加审计或库存 |
| 无效认证 | 拒绝执行，受检事实不变 |
| owner、source、ledger 建连停顿 | 分别注入建连停顿，8 秒预算下约 8.01–8.02 秒退出，前面已打开的连接无残留 |
| 插入后提交前停顿 | 临时截止/审计回滚，原请求恢复为未记录 |
| 工作进程 SIGSTOP | 父进程到期终止并回收它，后端连接消失，临时记录回滚 |
| COMMIT 后停顿 | 实际提交后丢失观察，原请求恢复到准确记录，没有重复写入 |
| COMMIT 后只发管道消息头 | 接收方仍按总期限退出；实际提交的截止可准确恢复 |
| 父进程 SIGKILL | 在临时记录已写入时终止父进程，工作进程因存活管道断开退出；临时记录回滚 |
| 库存和审计复核 | 六张库存事实表前后摘要相同；三份截止、三份审计、原始来源/账本及五个比较粒度逐项一致 |

建连停顿与回执丢失是合成注入；数据库事务、进程信号、后端断开、回滚和恢复均实际执行。
没有向外部数据库或业务系统发送请求，也未关闭数据库守卫。

首次会话 `22636` 因检查脚本把单表摘要与整个摘要字典比较而退出 1；第二次 `54351`
完成正常提交/恢复和三种建连停顿，但 5 秒预算下没有到达提交前注入点，退出 1。
两次失败和实例日志保留，不能作为对应场景通过证据。最终 8 秒预算执行全部 12 场景。
