## 运行时与边界

- 平台 `linux/arm64`，沿用已有官方 PostgreSQL 16 Alpine 基础，增加 Python 标准库解释器。
- 镜像摘要：`sha256:b0d210974e21e68b0b6c4b44acb7e4a005f07c416b75b7a6a900a2f41b54c311`。
- 实际工具版本：Python **3.14.7**、psql/pg_dump **16.15**。
- 使用 `postgres` 非 root 用户、只读根文件系统、关闭网络、64 进程上限和 128 MiB
  内存运行监督场景。源文件只读，临时目录在 16 MiB tmpfs，未挂载数据库数据目录。
- 正常命令保持输出 `CONTROLLED_NORMAL`，退出 0；0.3 秒期限的等待命令退出 124，
  两个监督记录都证明私有暂存清理。两种容器均 `--rm`，最后精确查询无运行容器。
- 本批只运行本地 `nerdctl/containerd`，不能当作 Docker CLI stdin 关闭、存活信号缓冲、
  挂起恢复、实际 PostgreSQL 长查询或整个 Compose 备份的证据。

## 保留的失败和准确成功链

1. 会话 `45027`：构建器拒绝 host 网络权限。未扩大构建器权限，改用默认隔离网络。
2. 会话 `74465`：Dockerfile **构建成功**，但随后客户端探针的 shell/Python 双层引号错误
   导致 NameError，整项检查退出 1。构建输出固定上述 manifest，不能把探针失败报成镜像没构建。
3. 会话 `64865`：修正探针后重复构建在 60 秒观察上限超时，退出 1，VM 已停止。
   后续复用已成功导出的自有镜像，不再重复请求构建。
4. 会话 **48479**：直接检查缓存镜像摘要与第二次实际构建输出相同，修正后的客户端及
   两个真实容器监督场景通过，退出 **0**，VM 已停止。`imageBuilt=false` 表示本次没有
   重新构建；构建证据来自第二次日志，二者用完整摘要关联。

所有源文件、命令、版本、三次失败与最终通过保存在 `oss-backup-runtime-20260921`；
