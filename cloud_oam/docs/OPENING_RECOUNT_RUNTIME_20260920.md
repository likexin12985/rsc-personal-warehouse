# 正式发布样本下的复盘、并发与权限验证（7.69）

本批补齐一条实际第二轮复盘链。此前 7.67 的“recount”样本只表示复盘备用库位，
当时运行的是首轮零盘点，不能据此声称验证了重新指派和第二轮实盘。本批通过真实
PostgreSQL **16.15** 上的正式服务补齐该证据；没有修改生产服务、迁移、客户端或权限。

## 已验证的业务结果

使用新临时库中的合成数据，经真实签名接收、来源授权、物料审核发布和控制库存发布，
产生一条明确为零的控制行。应用授权、HMAC、数据库约束和 COMMIT 均使用真实实现。
只有外部来源/文件存储传输为合成样本，不把本批计作 OAM/飞书实数验收。

1. 持真实 JWT，经 `/api/v1/stocktakes/opening/from-publication` 选择正式发布批次启动；
   同请求重试回读原任务，启动业务事实不变。
2. 首轮实际盘点 **2 件**，区域复核要求复盘；指定另一位有本区域权限的负责人，
   追加第二轮，不覆盖首轮实盘、差异、提交和审核记录。
3. 将其他区域负责人指派为复盘执行人时，返回 `opening_recount_assignee_scope_forbidden`；
   合法指派后，原执行人及其他区域人员提交第二轮实盘均拒绝，全部受检业务事实不变。
4. 新执行人第二轮实际盘点 **3 件**；区域、总部复核后只按第二轮过账 **3 件**。
   两轮提交各只有一份完成事实，整个任务只有一次过账；首轮证据在关闭后仍完整保留。
5. 首轮计数、第二轮计数和过账分别有两个真实 API 事务竞争同一幂等键；均观察到
   `pg_blocking_pids` 锁等待。先提交者的快照在第二事务获准 COMMIT 前采集，随后核对
   第二事务回读原结果且没有追加事实。同一实盘键改成 4 件时拒绝，事实不变。
6. OAM 控制零与本地实盘 3 件保持两种事实。控制差异未处理时禁止关闭；区域解释及
   独立总部人员批准后关闭。对账不改库存交易、移动、余额、账本游标或 SN 位置。
7. 另一任务的计数事务实际等待人员授权写锁；竞争事务提交撤权和授权版本更新后，
   旧权限请求失败，盘点/复盘/审核/过账/对账/库存/审计/Outbox 共 **51 张表**的受检
   快照不变。授权事实是该场景的预期变化，不把它们混入“业务未变化”的断言。
