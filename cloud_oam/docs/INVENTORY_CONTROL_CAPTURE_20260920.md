# 本地库存控制采集与持久证据（7.47）

接续 7.48 已增加摘要声明的隔离认证接收与不可变凭据，控制上传现在必须同时配置密钥版本并
取得准确凭据回执。见[最新采集凭据与权限说明](INVENTORY_CONTROL_ATTESTATION_20260920.md)。
以下内容保留 7.47 当时的实现与验证边界，不能作为 7.48 当前状态。

依据正式 V1.0 基线继续 B1。本批把已有的覆盖证据契约接到本地只读采集器，并验证采集、实际
HMAC 验签、隔离暂存和不可变准备记录的衔接。全部验证使用合成来源与隔离 SQLite，没有读取
真实 OAM、安装或启动调度、上传业务数据、批准来源/目录、提交、推送或部署。

## 已实现范围

- `edge_sync/inventory_control_capture.py` 接收独立目录，严格绑定来源、企业、组织、范围、目录
  版本及库位区域。采集前后重新分页检查当前仓库目录，类型或范围变化即拒绝，不从库存反推库位。
- 每页必须明确返回成功、整数总数和完整记录列表，校验页数、稳定总数、重复记录和库位映射。
  总数缺失、异常响应、短页、跨范围和未知库位均失败；零库存必须来自明确成功的零条第一页。
- 记录只保留既有库存字段白名单。缺省展示坐标只继承准确查询及当前仓库目录的同一绑定；与绑定
  冲突的原始字段不覆盖。未知来源更新时间保持未知，不用采集时间冒充业务更新时间。
- 实际上传清单和批次与证据共用生成器，全量根与增量删除链可由后端覆盖校验器重建。
  本地历史指针、目录版本、快照、最终摘要、记录数及逐条索引必须吻合，否则在新读取前阻断。
- 上传前以 `0700` 目录、`0600` 文件、独占创建和文件/目录 fsync 保存证据；同名文件不得覆盖。
  成功后保留证据，状态只记录精确文件名和 SHA-256。证据含业务数据，应留在受保护的本地路径。
- 所有上传改用现有 `CodexLocalEdge/edge_http.py`，无直连或 Windows 执行兜底。只读采集通过共享
  OAM 客户端，不调用登录接口；未知响应不重试、不回显原始响应或凭据。
- 批次与完成回执检查准确 ID、模式、记录数及摘要。错误/未知回执不推进状态；写本地状态失败时
  不推进内存索引。若文件替换已完成但目录同步失败，磁盘状态可能已改变，必须下一次先回读。
  原 outbox 与证据保留，下一周期隔离旧包并重新查询来源，禁止盲目重放。
- 安装器复制新增模块；隔离安装测试只执行复制函数，使用合成客户端验证安装后 `--help` 导入。
  CI 显式测试清单补入采集及 7.43—7.46 的准备、授权、配置和交接测试。

## 使用边界

新模式需要显式 `--control-catalog-file`，且只接受 `--entity inventory`。例如在已有受控本地
配置下，从 `cloud_oam` 目录执行只读预检（占位目录不能用于真实采集）：

```bash
.venv/bin/python edge_sync/oam_edge_sync.py \
  --entity inventory --warehouse-code EXACT_WAREHOUSE_CODE \
  --control-catalog-file /absolute/private/reviewed-catalog.json \
  --state-file /absolute/private/control-state.json \
  --outbox-dir /absolute/private/control-outbox \
  --lock-file /absolute/private/control-sync.lock \
  --dry-run
```

目录采用已有 `rsc.inventory_control_coverage.v1` 契约，范围必须与上述参数完全一致。独立文件
输入本身不表示目录已获 0113 授权。建议控制采集使用独立状态/outbox 路径，避免与通用镜像状态
混用。旧通用镜像状态缺少覆盖证据、目录变化、索引损坏或链达到 64 段时，须明确重新全量采集；
程序不自动把不完整历史解释为空基线。dry-run 不上传或保存证据/索引，仍使用本地互斥锁。

本批没有改变现有调度器的采集模式或运行状态；默认 `--entity all` 仍为通用镜像同步，不自动
生成控制证据。生产采集与上传继续遵循原有授权、共享会话、精确健康检查和回读规则。
