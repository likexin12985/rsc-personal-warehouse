## 业务行为

区域负责人可以核实本区域已提交的报损。系统保存独立不可变核实事实，包含准确原单、
原预检摘要、资产组织、当前核实人和权限版本、核实意见、请求/幂等键、审计、状态事件、
Outbox 和申请人通知。该事实仅表示 awaiting_headquarters，stock_effect 为 none。
原报损单继续为 submitted，所有原冻结份额和准确 SN 都继续保留；不生成库存流水，
不代表总部批准、报废、退回、解除保管责任或消息送达。

一张原单当前只允许一个区域核实结果。原请求准确重试回读原结果；改变核实人、原单、
意见、请求 ID 或幂等键均不能覆盖原结果。该核实键空间独立于库存过账和报损提交。
后续若增加总部退回后的重复区域核实，需要明确的追加事实与前置状态，不能覆盖本记录。

审核人必须当前在职、账号/身份有效，有准确资产组织的区域角色和核实授权，并遵守
所有适用 deny。申请人不能自审；总部角色本身不能替代区域核实授权。数据库在 COMMIT
再次检查当前身份、角色范围、权限版本和真实到期时间。

原申请人后续停用，不影响当前区域负责人处理遗留报损：历史提交用独立身份坐标验证
原始内容、照片、流水、审计和通知，不伪造当前申请人登录主体，也不要求其恢复登录。

## 数据库与权限

新增 stock_loss_regional_reviews，真实外键仅能绑定 loss_report 原单；API 仅 SELECT/INSERT。
函数私有、固定来源 hash，触发器 ALWAYS；禁止改写、删除或清空核实历史。
缺审计、状态、Outbox、通知，或伪造自审/范围/版本/hash/授权时整笔回滚。
区域核实作为库存来源单据过账被直接拒绝。空库允许往返，保留核实历史时降级被阻断。
SQLite 迁移保持区域写入关闭，仅服务组合测试使用独立内存模型夹具。

本机与 CI 共用报损完整 PG16 检查主体，追加核实、请求者停用、提交时效、并发和
历史保留探针，不删减之前提交/封存/共享冻结的断言。
