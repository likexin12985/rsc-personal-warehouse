## 本批修复

真实 PG16 首次走到库存快照完成时，0044 数据库封存检查拒绝了请求：接收端保存重新序列化
后的 JSON，却保存原签名 HTTP 正文的 SHA。时区 `+00:00` 转成 `Z`，或空格、键顺序变化，
都会造成原文与摘要不一致。现在先验证签名正文、正文 SHA 与已解析请求一致，再保存准确
UTF-8 原文；原文相同重试返回原结果，重新编码后的不同正文仍冲突，不覆盖完成事实。

控制准备、工单投影和收货投影统一核对保存原文的 SHA，另行检查解析后的字段含义。测试
覆盖时区、空白和键顺序、准确重试、改变正文的冲突及直接调用时的正文/摘要/请求不匹配。
既有 0044/0112 SQL 约束没有放宽，没有重写历史快照。若已有历史正文与摘要不一致，仍拒绝
使用；真实历史数据的审计和有据修复属于上线迁移验收。

非零整链通过后，生产 Edge 启动校验还发现目录遗漏：0119 已存在的四个物料版本图触发器
没有列入共享 OAM 范围校验。现在校验准确函数签名、源码 hash、固定 search_path、私有
执行权限以及四个 ALWAYS 触发器的类型和延迟属性。额外触发器、错误 search_path 和
越权 EXECUTE 分别在新建合成库内用随后回滚的事务验证，均拒绝；原状态恢复后启动通过。
没有禁用触发器或给予运行角色新权限。
