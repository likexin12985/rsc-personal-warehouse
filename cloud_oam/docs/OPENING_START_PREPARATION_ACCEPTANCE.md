## 四层契约

前缀为 `/api/v1/stocktakes/opening/start-options`，均为 GET：

| 路由 | 必须绑定的选定坐标 | 分页游标 |
| --- | --- | --- |
| `/regions` | 无；仍必须验证当前正式管理身份 | `after_id` |
| `/asset-owners` | `region_org_id` | `after_id` |
| `/locations` | `region_org_id`, `owner_org_id` | `after_id` |
| `/assignees` | 上述坐标及 `location_id` | `after_person_id` |

每页绑定当前 `actor_person_id`、`authorization_version`，固定 `schema_version=1.0`，
并始终返回 `start_ready=false`、`control_evidence_status=control_evidence_not_evaluated`。
不返回控制数量、SyncRun、任务/范围 UUID、hash 或幂等键。执行人的 `assignee_user_id`
必须是真实 `users.id`，不能用 `person_id` 替代。资产所有组织与物理所有组织允许不同，
但必须满足原启动服务的组织树/授权组合；个人仓须为有效叶子、当前精确保管人工程师。
区域仓可有个人子仓，负责人未配置时保持空，不生成角色/人员。

分页 limit 为 1–100；未知或重复查询参数拒绝。只回显本页最后一个已授权返回对象作游标，
私有 lookahead 不公开。每批最多扫描 100、每次最多 1000 个原始候选；无法在上限内确认
完整页则整体 503，不返回部分结果或外部身份游标。响应及框架错误都采用 private/no-store。

## 授权与并发读取防护

完整 principal 的 deny 与单个 manager grant 的 allow 同时执行。当前用户、验证身份、
权限版本、授权/权限矩阵、组织父链、库位父链和保管关系从数据库重新加载；原始不可变
签名避免 ORM 对象刷新把读取期间的变化隐藏。返回候选及私有 lookahead 都需要复验。

读取结束前再次检查发起人与所选范围，然后在所有数据库操作之后采样时钟。独立有效期
截止点覆盖当前授权/保管到期和已有未来授权/保管开始，包括当前尚无保管关系的区域仓。
到达边界即整页拒绝；不用无限重读或缓存延长许可。它不是跨请求权限租约：实际 POST
仍须独立加锁重验，也不承诺响应后管理数据永远不变。

漂移专项 33 项通过（独立执行 10.82 秒）。修复前真实复现的 7 项时间窗失败均已转绿，
包括返回候选/lookahead 到期、未来 deny 激活以及库位保管关系开始/到期。
专项也验证末次时钟后无 SQL、业务/库存/审计/outbox/同步证据逐表不变。
SQLite 的读取窗口模拟不是 PostgreSQL 双会话并发证据。

真库门禁新增真实 `star_oam_api` 登录、`READ ONLY` 事务、四层正向/连续分页与真实用户映射；
编译 SQL 检查只允许十张身份/组织/位置引用表的 SELECT，拒绝行锁、SQL 函数和库存读取。
明确标记的临时权限矩阵夹具在隔离事务回滚后核验还原，不把 `SET ROLE` 冒充真实登录。

## PC 只读入口

既有期初盘点页增加默认折叠的准备面板；必须同时具有管理员/区域负责人角色及
`stocktake.manage` 权限，页面仍保留原 `stocktake.read` 路由门禁。每层响应严格匹配当前
人员、授权版本、层级坐标及末项游标，跨页重复人员或用户整页拒绝。
上级选择变更、刷新、分页与错误都先清除相关选择和后代；切换身份/授权版本会重挂面板，
迟到成功/失败响应和卸载后的响应不得重新填回。保管人和初盘执行人不是同一个字段，
个人仓执行人还须与当次展示的保管人一致。

运输回归通过真实 `apiNoReplay`/fetch 证明 401 仅发出一次 GET：无刷新 POST、重放或
localStorage 写入。目录不新增持久状态，不清除或重用既有 count 恢复哨兵，不改变计数、
复盘及其他写命令。界面始终标明控制库存未评估，不能启动。

## 微信小程序只读入口

只修改既有 `formal-stocktakes` 页及新增两个工具模块/专项测试，没有增加 page 注册、
release 地址、个人主体配置或生产权限。仍要求真实管理角色与正式 read/manage 权限匹配。
每次目录调用在前后分别只读复验身份与权限；无自动 401 刷新或重放。onShow、整页刷新、
onHide、onUnload 与身份/授权版本变化清除准备状态，可撤销的内存读标记阻止迟到响应恢复
旧名称或下游选择，不借用 count 的任务锁或持久哨兵。

picker 的第 0 项是无业务 ID 的“请选择”；值 0 只清空当前级和后代，不请求下游、不猜测
首个人员/库位。真实项用 1–n 显式映射，刷新、分页及上游变化后归零，消除原生索引残留。
Node 回归验证绑定和处理逻辑，但微信原生弹层/生命周期仍待隔离真机验收。

“无存储/POST”只适用于新增准备目录链：既有列表加载仍有原来的 `api.get` 和 `setUser`
会话维护，不宣称整个页面完全不写会话。新目录不写准备数据或业务状态，也不开放启动。

  V1.0 同时允许全量与增量同步；一期是否仅以完整省级快照建账仍待用户确认，不能把
  `SyncRun.mode=full` 单独当作省级覆盖证明或既定基线要求。
- 多范围/分阶段建账时控制批次复用策略；不能擅自增加全局唯一约束或把空批次当作零库存。

- 微信真机、部署/容器和隔离业务 UAT。
