## 当前源码确认的缺口

- V1.0 要求按 `scope / external_snapshot_at / local_ledger_cursor` 固定两侧事实，明细按
  仓库、SKU、成色记录差异；正式上线前至少连续三天的省级差异均须有明确解释。
- `formal_reconciliation.py` 目前只有 `/v1/reconciliations/opening`。现有通用对账表的
  0026 守卫绑定期初任务、轮次、成立流水和命令；不能直接插入 `daily:*` 来绕过它。
- `control_projection_lines` 为省份、SKU、成色汇总；仓库、库位和原记录数量保留在
  `control_projection_origins`。日终明细须从已证明的完整 publication/origin 图恢复，
  不能把省级汇总行按名称猜成一个本地仓库。
- 新系统流水有事务化 `inventory_ledger_heads.next_cursor` 与连续交易游标。日终不能
  用当前 `stock_balances`、`posted_at` 或业务生效时间冒充此前某个游标的库存。
- 目前没有日终专用的不可变截止快照、仓库/位置映射版本、差异解释命令链和正式接口。

## 本批计算行为

候选位于 `artifacts/daily-reconciliation-20260921/daily_reconciliation.py`，只有标准库依赖；
不导入应用配置、数据库、网络或 provider，没有库存写入或自动审批能力。

- 输入包含来源 publication ID/hash、目录 hash、完整仓库覆盖清单及 origin 行；校验内容
  hash、记录数量、唯一 origin/业务键、数量精度与仓库范围。来源缺仓、缺行、重复或摘要
  不一致时拒绝；只有完整覆盖证据下的缺失 SKU 才能作为零比较。
- 固定本地交易游标，重建借出/借入的有符号流水。核对连续游标、完整明细、唯一交易、
  posted 状态、有效端点、同 SKU 转移及每笔事务后的非负余额；后续流水不改写历史结果。
  只使用新系统已经入账的事实，不重放 OAM 历史镜像来生成本地库存。
- 占用、拣货等状态之间的转移保持数量守恒；冲销是保留原交易并增加准确反向流水，
  重复、残缺或指向未出现原交易的冲销拒绝计算。
- 仓库与本地位置通过显式版本化映射关联；本区域任何参与流水的位置未映射即拒绝。
  地域必须由可信组织/位置快照解析，不能使用姓名、城市、用户省份或当前页面做推断。
- 纳入哪些库存状态必须明确配置。被排除数量仍按仓库、SKU、成色、状态逐项列出，
  不把不同物料单位相加。其他区域的账户不进入本区域差异。
- 使用上海业务日期，保留来源和本地观察时间及显式偏差预算；本次日对账截止必须等于
  采集时观察到的账本头。日期不符、无时区、偏差超预算或旧游标冒充当前采集均拒绝。
- 两侧按仓库、SKU、成色做完整左右比较，只计算 `external_qty - local_qty`，不相加。
  报告 hash 绑定两侧快照、游标、映射版本和状态范围；返回对象的修改不改变输入事实。

测试包含 8 笔已入账交易的占用、个人位置转移、消耗、冲销、跨仓/跨区域调拨和成色变化。
三个比较粒度的本地量分别为 **7 / 1 / 5**，与手工预期一致。21 项初检后补充三项来源
聚合、跨物料排除量与空账本边界检查，最终为 24 项，不累计成 45 项。
