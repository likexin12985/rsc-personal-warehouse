# 实物出库过账验收

本批遵循 V1.0，在 `codex/production-readiness-gates` 增加独立实物出库。
新迁移为 `20260912_0072`，已发布的 0071 和更早迁移保持不变。

## 实现范围

- 按原拣货事实与原出库行分批过账；累计数量不得超过已拣货数量，SN 必须属于原拣货且未出库。
- 原出库单/行保留拣货时快照。新增不可变 `outbound_postings` 和 SN 绑定，
  当前累计出库量与最后出库时间从这些事实读取，不能把原单的零值快照当作当前履约进度。
- 使用明确传入且重新核验的唯一预置在途账户；所有权、保管人、位置、SKU、成色与批次
  沿用原绑定，仅库存状态从 `picking` 转入 `in_transit`。不自动创建账户或推断交接责任。
- 库存交易、流水、余额/SN 投影、需求命令/版本、状态事件、审计与 Outbox 同事务提交或回滚。
  同一原单可多次出库；共享拣货账户的余额必须覆盖全部未出库的原单份额。
- 每条最终批准明细全部出库后，需求出库轴才进入 `outbound`。部分出库仍保留待拣齐/
  已拣齐状态，由逐笔出库数量表达进度；批准但释放的数量未取消时仍属于未完成部分。
- 网页支持出库数量、SN、备注与复核。提交前刷新身份、权限、需求、原拣货和余额坐标，
  保存原请求后最多一次 POST；网络结果不明时仅按原追踪坐标 GET 核验，并暂停其他写入。
- 历史恢复重新证明原身份、当前权限、原拣货、出库事实、流水、命令、审计及状态事件；
  后续出库完成后，原拣货请求仍可恢复，不能用当前出库状态改写历史拣货结果。
- 0072 增加最小 SELECT/INSERT 权限、始终启用的不可变保护、原单绑定和延迟事实关系校验，
  精确函数哈希与触发器目录，并以可逆源码替换扩展原有状态守卫。存在出库事实时禁止降级。

## 接口

- `GET /api/v1/material-requests/{id}/outbound-options?request_line_id={line_id}`
- `POST /api/v1/material-requests/{id}/outbounds`
- `GET /api/v1/material-request-outbound-command-status`，携带原 `X-Request-ID`

写入须携带需求版本、原拣货 ID、绑定在途账户、出库数量、源余额版本/游标、SN、备注及
独立幂等头。所有响应禁止缓存；读取须通过当前范围、期初及投影完整性校验。
