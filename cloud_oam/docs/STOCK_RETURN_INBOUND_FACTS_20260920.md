## 0111 迁移及权限

审计发现 0103 的出库守卫仍拒绝所有后续退回在途转出，即使0106入账事实合法也无法通过
真实 PostgreSQL。0111 精确替换记录在案的旧函数分支：只有绑定独立入账并通过完整校验的
`stock_return_receipt_inbound` 事务才能通行。来源类型字符串本身不授予转出能力。
历史 0103/0105/0106/0110 文件保持不变，旧源码及替换后源码哈希均受目录校验。

新增两个 owner 私有函数和十个 `ENABLE ALWAYS` 的提交时延迟 INSERT 触发器，覆盖四张
入账事实表、事务、流水、流水 SN、审计、状态和 Outbox。新入账追加时检查当前接收权限；
历史原图重证使用保存的责任与时间，不要求旧操作者永久保持相同授权版本。
新函数固定 `search_path=pg_catalog, public`，撤销 PUBLIC/API EXECUTE，没有增加 API 表权限。
当前物资流程安全目录为 **90 个函数 / 297 个触发器**；readiness 哈希为
`13c5383d20ecc1bbb4a503a19dbd92f52259a61eea7a19d6c7fd3747f8109e13`。

本次升级在版本表和受影响表的锁内执行预检。发现旧独立入账或使用该类型/业务键的库存事务，
会停止升级，保留全部数据并要求调查；不自动补造、重写或删除历史事实。已有入账也禁止降级。
因此本迁移不是已有生产入账数据的自动升级方案；若部署预检发现这类数据，需要单独审查。
SQLite 验证迁移顺序、保留与结构，不能证明 PostgreSQL 提交时约束。
