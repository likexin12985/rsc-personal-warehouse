## 接口与事务边界

- `POST /api/v1/reconciliations/daily/{cutoff_id}/commands`：开启审核、逐项解释、指定项目退回补证、总部独立审核。
- `POST /api/v1/reconciliations/daily/{cutoff_id}/command-status`：使用原完整命令、原幂等键和请求号查询原回执。后续审核不会改写原提交的结果。
- `GET /api/v1/reconciliations/daily/{cutoff_id}/history`：仅返回操作、人员、时间、解释及退回意见，不返回会话、令牌或幂等键。
- 列表、详情、逐项分页返回真实审核状态和版本；解释分页和历史分页支持 `expected_review_version`，版本变化返回 409。

命令要求 Bearer JWT、`Idempotency-Key`、`X-Request-Id`，路径、正文和请求头必须一致。正文仅包括 `expected_authorization_version` 和严格判别的 `command`，不得传数据库地址、操作者、权限或来源事实。命令不接受仅 Cookie 认证。

HTTP 使用固定独立进程，当前会话、角色、数据库连接、SQL、Python 工作和 COMMIT 处于同一个 15 秒期限内。每 API 进程最多 4 个命令工作进程，数据库语句使用剩余期限；父进程丢失或期限耗尽会终止自有子进程。清理另有最多 1 秒等待，操作系统调度不是硬实时承诺。若不能确认回收，保留容量槽并拒绝继续无限创建子进程。

超时、提交回执丢失或无法确认结果时返回 `daily_review_outcome_unknown_use_exact_recovery`，不会自动重发。客户端必须保留原命令并查原回执；恢复缺少记录不等于原请求绝对未发出，须在工作进程已终结和当前查询成功的边界下解释。

## 日终专用证据

用途为 `daily_reconciliation_evidence`，沿用正式上传意图、完成验证和短期私有下载接口。上传需要当前区域负责人对有效区域的 `reconciliation.read` 与 `explain_daily` 权限。SQL 和应用都检查已完成文件、用途、提交人及解释者身份，阻断旧收货附件混用和更换元数据冒充证据。

尚未关联的附件仅当前上传人可下载；关联后，下载人须能读取该文件全部历史关联区域。总部具有全国查询范围；工程师、外部审批身份和外区账号无权获取签名地址。解释、审核、附件审计独立保存，审核不生成库存流水。

0133 不改写旧文件或历史事件。若旧日终审核使用其他用途附件，升级阻断，等待明确历史迁移方案；新用途文件一旦存在，回退阻断以保留证据。来源配置、收货异常、库存作业等原附件用途和历史保持。
