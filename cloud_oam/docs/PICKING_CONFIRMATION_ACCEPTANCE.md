# 正式拣货确认验收

本批沿用 V1.0 基线，在 `codex/production-readiness-gates` 增加正式拣货确认。
迁移 head 为 `20260911_0071`；发布过的 0069、0070 迁移保持原样。

## 已实现

- 按原占用分批拣货，数量守恒为 `原占用 = 已释放 + 已拣货 + 仍占用`。
  候选 SN 必须属于本笔原占用、未释放、未拣货，且仍处于原占用账户。
- 必须使用预置且唯一匹配的拣货账户；所有权、保管人、位置、物料、成色和批次均不变。
  候选展示批次、成色、原占用、释放、已拣货和可拣货数量，不猜测或自动创建库存账户。
- 确认时追加出库单、出库行、拣货事实与 SN 绑定，通过正式库存内核执行 `reserved → picking`。
  库存流水、余额/SN 投影、需求命令、版本、状态事件、审计及 Outbox 同事务提交或回滚。
- 原占用和分配不重写，也不重新开放已消耗分配额度。共享占用池扣除其他需求已拣货的份额，
  避免把正常移出的库存误报为不足；余额必须覆盖所有剩余原占用。
- 需求部分拣货保持 `pending_pick`；每个当前批准明细均拣齐后才进入 `picked`。
  出库单已拣货但 `outbound_at` 为空、`outbound_qty = 0`；发运及之后状态不变。
- 网页支持数量、原 SN 选择和备注；持久保存原请求后仅发送一次 POST。
  网络结果不明时保留恢复记录，暂停需求其他写入；按原追踪坐标只读核验，不自动重发。
  历史回读验证原身份和当前权限，以及原命令、出库行、库存流水、审计和状态事件。
- 0071 为新表配置最小 SELECT/INSERT 权限、始终启用的不可变保护、延迟事实关系校验、
  精确运行时函数哈希和触发器目录。空图可逐级降级再升级；存在拣货事实时拒绝降级。

## 接口

- `GET /api/v1/material-requests/{id}/reservation-pick-options?request_line_id={line_id}`
- `POST /api/v1/material-requests/{id}/reservation-picks`
- `GET /api/v1/material-request-reservation-pick-command-status`，携带原 `X-Request-ID`

POST 必须携带需求版本、原占用、数量、源余额版本与流水游标、SN、备注及独立幂等头。
所有响应禁用缓存。候选读取重新核验身份、范围、期初、投影和历史证据，并限制记录数量。
