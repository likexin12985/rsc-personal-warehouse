# 0164 审计锁范围修复发布说明

状态：候选及合并后的主树验证均已完成；提交和 GitHub 状态以 Git 及当前机器回执为准，未部署生产。准确源码位置及进程终态以 `CONTINUE_DEVELOPMENT.md` 和 `artifacts/authentication-fence-0164-next/current.json` 为准。

## 问题与结果

0161 报损纠正封存守卫对包含操作者和请求编号的普通审计也锁定库存流水头。真实登录会话因此等待无关库存事务；授权发布持有人员锁时，可能与持有库存锁的期初任务互相等待，形成死锁。

0164 调整 `rsc_fence_loss_correction_seal_0161` 的审计范围：库存和需求审计继续执行库存锁及封存检查；其他业务域的普通审计独立提交。下列三种封存对象不享受审计域豁免，即使被错误标成 authentication 或 authorization 也仍受约束：

- `stock_loss_inverse_request_seal`
- `stock_loss_correction_approval_seal`
- `stock_loss_correction_execution_seal`

报损、逆向冲销、审批和库存过账的事实守卫、幂等绑定、历史保留、通知和恢复规则不变。认证会话本身的身份、频控、会话及审计保护仍由各自正式入口负责。

## 迁移与权限

前驱为 `20261212_0163`，新版本为 `20261213_0164`。迁移只替换精确冻结的守卫函数和当前版本准入函数，不改写库存、会话、审计或业务单据行。

必须使用 PostgreSQL 16、READ COMMITTED、直接连接的非超级用户 `star_oam_migrator`。迁移先验证两个前驱函数的定义、属主、配置和 ACL，任一漂移均拒绝；不会静默覆盖漂移函数或扩大 API 权限。升级后，应用启动检查新函数摘要和完整权限边界。

应用、任务入口、版本准入检查及迁移应作为同批发布。迁移需要锁定审计、状态事件和库存头相关表，应按现有维护窗口流程执行。生产迁移仍须独立授权和书面验收；本说明不构成执行许可。
