# 通知原始目标人员的持久留存

本节是未提交的 7.36 切片，接续 [来源异常复核](INVENTORY_NOTIFICATION_OPERATIONS_20260920.md)。
后续 7.37 已补[原目标查看与显式恢复](NOTIFICATION_TARGET_RECOVERY_20260920.md)；本文件保留 7.36 的历史范围与证据。
V1.0 要求库存变化通知到实际人员；原实现只记录已解析的渠道接收项，人员没有账号或可用渠道时，
事件扩展为零条后没有独立的原目标事实可供恢复。本次先补留存边界，尚未实现身份补齐后的恢复操作。

## 新事实与兼容边界

- `notification_person_targets` 固定事件与真实人员的对应关系，不依赖登录账号存在；有外键、
  事件/人员唯一约束，不允许用不存在的随机人员 ID 表示“尚未绑定账号”。
- `notification_target_bindings` 追加目标到接收项的关系，同一接收项只能绑定一个原始目标。
  创建时核验相同事件、账号实际所属人员及事件未取消；不把手机号或 openid 复制到目标事实中。
- `notification_events.target_manifest_sha256` 固定原目标全集。摘要原文为
  `notification-person-targets.v1`、换行符、去重并按规范 UUID 字符串排序后以逗号连接的人员 ID。
  空目标集也有非空摘要；历史 NULL 表示原目标未留存，不能将它解释成“确定无人需要通知”。
- 新通知同 key 重放必须匹配原业务事实和已留存目标；原事件、目标、绑定、业务事实、审计及
  Outbox 仍由调用方在原事务中统一提交，通知函数不会自动提交或提前 flush 调用者的 Outbox。
- 历史事件保持 NULL，不从当前账号关系补写原目标。已有目标但零条渠道接收项的事件，即使状态
  已为 `expanded`，目标也会保留。expanded、queued、sent、delivered、read 和个人仓入账分别记账。

专用工单、入账、退回通知已有原目标时，通用库存消费者不会因其暂无渠道再创建第二条同人员
通知；其恢复应归原事件处理。首次通用库存通知的目标清单也不会因后来新增专用通知或账号变化
而重新计算。兼容字段 `already_notified_person_count` 在这里表示已由原通知覆盖的目标人数，
并非送达人数；历史 NULL 事件仅保留原有接收项去重，不生成新的历史目标事实。

## 0109 迁移与数据库权限

API 角色只新增两表的 SELECT/INSERT，不增加 UPDATE/DELETE/TRUNCATE，也不能直接执行守卫函数。
原通知运维能力、用户角色、公开首页和业务 API 授权没有新增范围。

目录包含新的函数族，未知同族函数也会被检查。目标全集使用初始延迟的约束触发器在提交时核验，

包括空目标事件。绑定必须满足准确事件/人员关系。SQLite 覆盖外键、不可变和绑定拒绝，不能代替
PG16 的延迟聚合约束、真实角色或并发语义。

## PostgreSQL 16 门禁接续

业务通知现在与老版本业务事实同时产生目标封存，正常降级会先触发 0109。旧门禁改为明确检验
该顺序，再在同一隔离 PG16 库中以 migrator 身份、显式回滚事务执行指定旧迁移自身的降级原语，
要求其准确拒绝原因；不删除目标事实、不改版本标记，不把 0109 的拒绝冒充旧版本通过。
无目标封存时，仍要求原正常迁移链返回原拒绝原因。

新增 `tests/pg16_notification_targets_gate.py`，在既有保护门禁末尾检验真实 API/migrator 身份、
零渠道目标留存、回滚、原目标重放、最小 ACL、owner 不可变保护、延迟摘要与防串人绑定。
源码已接入；本轮尚无当前候选的真实 PG16 终态，不能宣称上述真库场景已通过。

## 下一切片与上线缺口

1. 实现总部只读待解析目标列表，准确区分原目标未知、无账号、账号停用、缺少经验证渠道和已绑定；
   接收项为零不再作为通知成功的依据。
2. 身份补齐后的显式恢复需要原目标/账号关系、当前正式身份与 provider 范围证明、对象锁、
   独立幂等键和不可变恢复审计。只补合法的接收项，后续扩展和发送仍分别处理；unknown 投递不盲重发。
3. 原通知渠道解析仍使用旧 `WechatIdentity` 和账号 mobile，尚未完成按 app/provider 限定、
   正式 AuthIdentity 验证及真实供应商验收；不能把目标留存完成写成渠道已可上线。
   本次绑定仅证明创建时的事件/人员归属，不证明渠道身份已验证，不能单凭绑定存在放行实发。
4. 历史缺失 Outbox、扫描性能、真实飞书目录、预生产身份、恢复演练及真机/UAT 继续独立验收。
