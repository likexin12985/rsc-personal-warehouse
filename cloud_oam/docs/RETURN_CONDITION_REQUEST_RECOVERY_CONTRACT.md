首次提交在共享库存流水锁和当前新增动作授权之后、库存写入之前执行检查。回查先采集请求证据，再证明原入库和全部纠正历史，核对唯一原输入及完整请求；随后核对请求证据未变，最后重新核验当前查看权限和审计/库存观察边界。成色事件的库存过账键由事件生成，不等于客户端原始键的任何别名，因此必须同时校验准确过账与审计/状态的请求引用，不能只搜索原始键。

只有唯一已证明的首次提交可携带同一个公共作业单、事件、原输入和持久键登记。历史库存交易、审计和状态必须准确绑定该事件；通知待发送不改变已发生的库存事实。未找到记录仍返回 `unknown`，`retry_allowed=false`、`absence_sealed=false`，不能称为“未执行”。

封存是永久关闭一个准确旧请求，不是重新提交。必须以完整原命令及原始键申请，只能关闭当前用户自己的请求坐标；先验证当前查看范围和对应动作权限，再独立重建真实旧入库来源及原请求内容。历史来源和当前可执行库存分开，不因今日保管责任结束而伪造旧历史；也不能仅因可以查看历史就授予封存写权限。当前新增动作授权函数包含实物保管/可执行库存检查，不能直接当作历史封存授权函数复用。

封存提交成功后，旧请求迟到必须被数据库拒绝。新业务如确有需要，应重新读取当前来源、重新授权、生成新请求号和新键，经过用户明确的业务提交动作；不能自动重放或复用被封存请求。
