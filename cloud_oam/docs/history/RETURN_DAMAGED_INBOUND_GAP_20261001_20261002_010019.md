## 必须完成的修复范围

1. 验收保持独立且不可变。按准确原验收行把接受量拆为非破损份额和破损份额；`非破损 + 破损 = 接受`，拒收与短少均不计为已入库。SN逐件按验收标记分区，禁止选择其他SN补齐。
2. 原本成色已为damaged时，不得重复转坏、重复增加数量；原new/used且被验收为破损的份额不能进入new/used可用账户。明确持有成色与可用状态，保留成色变化的原始验收证据和库存移动。
3. 增加前向迁移，支持一份原验收行对应必要的独立目标份额；保留既有单份入库及所有原请求摘要。新事实须有明确版本，旧历史读取仍按原版本证明，不能悄悄重写过去账户或让旧请求恢复失败。
4. 同步修改统一过账命令、目标账户创建准入、入库明细/SN/过账关联、完整历史证明和数据库提交约束。API绕过Python后仍不能把破损份额入新件可用账户、丢失SN、超量或跨验收行绑定。
5. 更新服务预览、HTTP/前端合同、请求保存与恢复、数据库权限和启动目录。预览必须展示每个目标成色/状态及份额；响应丢失只查原请求，不能自动重发。
6. 历史已错误分类的单据应能列入异常并走授权反向交易纠正，不得在升级时直接改余额。本地复现不代表生产存在同类单据，正式环境是否受影响须另行获授权精确查询。
