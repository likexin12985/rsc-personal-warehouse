## 业务行为

区域仓第一次接收某一 SKU、成色或批次时，验收后的独立入账现在可以在同一事务
建立缺失账户。既有账户按完整维度复用；两条相同维度的验收明细只创建一个账户。
预览没有建账副作用，验收本身也不创建余额或代替入账。

完整维度为资产组织、接收位置、保管人、SKU、成色、available 状态及批次。
新账户 ID 由服务端从完整维度稳定派生，客户端不能指定账户维度或任意替换目标。
已存在的同维度账户优先复用；派生 ID 如已被不同维度占用则拒绝，不选择随机替代。
既有预览 DTO 与请求摘要契约保持不变。

执行依次锁定账本与当前主体权限图，重新验证验收责任、请求封存、重复请求及计划
摘要，然后创建账户、调用统一库存过账并追加入账事实、审计、状态和通知。通知
渠道送达与入账仍是独立状态。任一后续失败都须完整回滚，不能单独提交空账户。

## 数据库边界

0149 从 0145 的准确账户准入函数摘要追加合法分支，并将当前版本检查更新至 0149。
历史迁移保持原样，不新增表、业务权限或 API 函数执行权限。升级先锁版本及相关
事实表，以原/目标摘要进行替换；源码漂移会拒绝迁移。

新账户必须连接准确验收行、入账行、过账关联、交易、移动、保管责任与已成立期初。
首个余额版本必须为 1，游标与该交易一致，余额等于该交易的目标移动总和；创建
时刻等于首次交易生效时刻，不得早于期初或验收，不允许更早移动或出向移动。
0106/0111 的完整业务证明与当前权限约束继续独立生效。存在退回入账历史时，
0149 降级明确拒绝；应用回退不能通过删除业务历史来迁就旧版本。

## 批次来源的独立缺口

当前 OAM 控制源规范化仍会拒绝 lot / lot_and_serial：采集合同没有已验证的批次
字段。上面的批次测试用已支持的签名完整空快照建立真实零期初，再通过统一过账
生成合成库存，验证入账路径。它没有证明真实 OAM 批次控制数的发布或对账能力。
该缺口继续保留，不能猜测外部字段含义，也不能为通过测试而删除来源校验。
