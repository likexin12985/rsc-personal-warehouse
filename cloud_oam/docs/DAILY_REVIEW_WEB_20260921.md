## 已实现

- 数量保持十进制字符串，用整数千分量核验左右差额；拒绝 JavaScript 不安全整数、错误对象、摘要、分页游标和审核版本。不将失败响应显示为空列表或零数量。
- 详情、明细和历史按同一审核版本读取；身份变化、撤权、过期响应、对象切换及分页版本冲突不会留下可继续操作的旧详情。页面当前只提供查询，没有提交或审核按钮。
- 审核命令和原请求查询支持现有 HttpOnly Cookie；Cookie 请求必须与服务端配置的 `OAM_APP_ORIGIN` 精确同源，生产必须 HTTPS。来源包含 `/xx`、未配置、跨站、子域、重复凭据或重复来源都拒绝；不从 Host 推断可信来源。
- 原 Bearer 接入保留，显式错误 Authorization 不回退 Cookie；认证、会话、当前权限、事务及 COMMIT 仍由原监督进程执行，前端不读取登录令牌。

`OAM_APP_ORIGIN` 是域名来源，例如 `https://rscwz.cn`，不是后台路径。Compose 已由 `APP_DOMAIN` 注入此值；独立运行服务时需显式配置。本批不变更数据库结构，HEAD 仍为 `20261112_0133`。

## 下一批必须先处理的依赖

现有 `/command-status` 要求完整原命令，不能只凭“尚未查到”释放页面的待核验记录。否则原请求延迟到达后，页面可能另起新键重复提交。应先建立只保存安全坐标的持久恢复协议，以及服务端永久不执行证明；原提交与终结操作必须共享锁、当前权限与数据库不可变约束。再接区域解释、专用附件、总部独立审核和退回补证。

不得持久保存 JWT、会话令牌或带签名附件地址；不得用超时或空查询推定未提交。仍需覆盖跨标签并发、刷新、换人、撤权、原命令延迟到达与回执丢失。
