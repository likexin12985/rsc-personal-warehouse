# 退回独立入账：服务修复与剩余门禁

2026-09-20，接续 7.39。工作树仍为 `codex/notification-delivery-worker`，未提交、推送或部署。
本批补充实际业务链测试；该链尚未达到上线标准。

后续 7.40 已实现独立入账封存表、0110 前向迁移和嵌套 seal 契约，见
[准确验收单封存](STOCK_RETURN_INBOUND_SEALS_20260920.md)。下文为 7.39 当时证据和缺口，
新封存实现情况以 7.40 为准；完整事实重证、页面已入账回读和真实 PG16 仍未完成。

## 本批修复

- 预览、计划摘要和持久化计划共用一种表示，补回必填 `reason`。新预览与新写入摘要同步变化；
  已保存的入账仍按原摘要回读，不重写旧事实。旧的未提交预览必须重新获取。
- 统一错误函数参数为错误代码、用户消息、整数 HTTP 状态码。找不到验收为 404，缺目标账户为
  412，无接受数量为 409；不再因错误状态类型或空过账命令变成无说明的 500。
- 预览、提交、重放和封存检查当前区域接收权限及原验收人。读权限仍可回查本人原结果，
  不能用于提交或封存。写操作先锁库存账本和正式身份图，保持调用方事务。
- 同 key 重放必须对应同一 receipt、操作者、request 和 plan；换 key 不再直接冒充原结果。
  按原 request 回读也检查 receipt，避免同一包裹多次验收时串单。
- 入账提交接入既有退回请求占用/封存检查，不能重用验收请求或任何已封存的退回请求。
  该检查不等于已解决下述独立入账封存表问题。
- 已完成入账的封存请求按 `request_hash` 比较原内容，并允许返回原入账结果，避免摘要误判
  或输出模型校验失败。通用冲销不能通过更改来源名称绕过原退回入账业务。
- 迁移测试发现安全清单遗漏 0106 两个守卫函数。本批补齐两个原始函数体的精确哈希、
  definer/void 类型、所有者与不可公开执行约束，并将 `_0106` 加入完整家族查询，防止隐藏
  未知函数。当前清单由 85 增至 87 个函数；没有改写数据库函数或放宽业务权限。

## 上线前仍必须完成

1. **独立入账封存事实与前向迁移。** 当前入账封存复用 `StockOperationCommandSeal` 的
   `receive_return`，只有 shipment，没有 receipt；7.39 尚未替换它。0105 的 PostgreSQL
   `rsc_guard_stock_operation_seal_0101` 要求 `stock_return.command_sealed` 及原验收封存正文，
   入账写出的 `stock_return_inbound.command_sealed` 和正文不符合此守卫。不能声称本地封存成功
   证明 PostgreSQL 可用。新事实要明确 receipt、request、hash、操作者、不可变审计和两连接
   seal/post 竞争；保留历史封存，未知归属不按包裹猜验收单。同步更新 readiness/manifest/ACL，
   通过准确前驱 hash 的前向变更完成，不编辑旧 0105/0106 来伪装已迁移。
2. **完整入账事实重证及数据库约束。** 当前 `_result` 仍主要投影入账行；应重证原验收、全部
   接受明细/SN、实际 inventory movements、两个账户的组织/责任/位置、请求与计划摘要、
   posting binding、不可变审计/Outbox/状态及无反向绕过。0106 检查有 receipt/posting 关联及
   明细维度，但没有覆盖上述完整图，不能因函数存在或语法通过就称防篡改完成。
3. **回读与小程序闭环。** 当前后端新封存输出为平铺字段，小程序要求 `{schema_version,
   lookup_status, seal:{...}}`；须在新事实实现时统一并用真实 HTTP 数据验证。收货页面只显示
   验收历史，未展示独立“已入账”事实，刷新后可能再次准备同一 receipt。补按准确 receipt
   查询已过账状态及原请求恢复，不能借用验收状态或新幂等键掩盖结果未知。
4. **PostgreSQL 16 动态证明。** 在现有受保护临时环境补真实 migrator/API role 的数量/SN、
   分批入账、原请求回读、不同 receipt 隔离、封存竞争、直接 SQL 伪造、撤权、故障回滚和
   不可变事实留存。当前没有本批 PG16 运行；不要用本机 PG18 或静态测试替代。

公开知识目录真实数据、候选代码的门禁提交方式和其余正式基线缺口继续保留；本批不改变这些边界。
