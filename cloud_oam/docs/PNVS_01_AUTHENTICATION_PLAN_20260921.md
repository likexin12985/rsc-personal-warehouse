## 1. 产品及官方依据

采用号码认证服务 PNVS 的 `SendSmsVerifyCode` 与 `CheckSmsVerifyCode`，服务端端点为
`dypnsapi.aliyuncs.com`。个人实名认证账号可使用平台预置签名和验证码模板；签名、模板须
配套选择。测试发送也计费，实际开通、计费及套餐归属需核对当前控制台，不能以普通 SMS
套餐采购记录证明 PNVS 可用。参考[新手指引](https://help.aliyun.com/zh/pnvs/getting-started/sms-authentication-service-novice-guide)、
[个人开发者接入指南](https://help.aliyun.com/zh/pnvs/use-cases/sms-verify-for-individual-developers)。

2026-09-21 已复核官方 API：发送当前仅支持国内号码；优先使用平台生成验证码，并保持
`ReturnVerifyCode=false`。发送与校验的 `SchemeName` 必须一致；`OutId` 用于准确关联本地挑战。
API 请求成功不能单独证明校验成功：`Model.VerifyResult=PASS` 才通过，`UNKNOWN` 是明确的
校验失败，不能与网络超时导致的“结果未知”混淆。详见
[发送接口](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode)、
[校验接口](https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-checksmsverifycode)。
实施前再次核对参数、SDK、返回码及服务限制；示例代码和示例号码不能直接作为生产配置。

正式环境只支持微信/手机号验证码无密码登录，不增加密码登录、找回密码或开放注册。
PC/H5 与小程序通过本系统后端认证；公开根首页继续查询，私有网页登录仍在 `/xx`。
个人主体小程序当前只注册知识查询页，私有登录联调使用隔离测试入口，不能因此改变当前发布包。

## 2. 当前源码初审：复用能力及差异

以下为源码和既有测试的只读核对，不是本次真实短信验收。

| 范围 | 已有实现 | PNVS-01 待补或复核 |
| --- | --- | --- |
| 供应商适配 | `backend/app/sms.py` 已有 `AliyunPnvsProvider`，调用两个 PNVS API；平台生成验证码、不返回明文、准确匹配 OutId/BizId，并关闭 SDK 和供应商自动重试。依赖已固定 `alibabacloud_dypnsapi20170525==2.0.0` | 沿用并复核 SDK 契约；不能把现状写成“尚未接 PNVS”，也不另建普通 `SendSms` 冒充认证 |
| 配置及凭证 | `backend/app/config.py` 已有启停、签名、模板、场景、有效期、间隔、手机号/IP 次数、失败次数及并发配置；`sms.py` 目前显式读取服务端 AK/SK | 设计 RAM 最小权限、云角色/STS 凭证链、轮换和失效处理；当前短信代码的云角色能力尚未完成。所有凭证只由服务端安全注入，禁止进入客户端、仓库和日志 |
| 挑战生命周期 | `foundation_models.LoginChallenge` 已区分 `local_hash`、`provider_managed`、`legacy_unknown`；平台模式要求 `code_hash IS NULL`。`formal_services/authentication_challenge.py` 已有用途、端类型、有效期、尝试上限、消费、独占 dispatch 及未知发送隔离 | 明确各历史模式的切换与退出策略，禁止伪造 code_hash、重开已消费挑战或把未知旧记录认定为已验证 |
| HTTP 与会话 | `routers/auth.py` 已接正式发送/校验、幂等结果恢复、挑战消费和会话事务；`authentication_session.py`、`authentication_session_admin.py`、`auth_sessions.py` 已有设备会话、刷新与撤销链 | 复核供应商校验成功但本地提交失败、响应丢失和重放的恢复边界；用当前代码完成客户端及 PG16 回归 |
| 身份与停用 | `authentication_identity.py` 只解析唯一正式身份，调用权限主体解析，允许基线规定的 `restricted_handover` 受限主体 | 验收本地账号、手机号、微信及 OAM 人员唯一关系；零匹配、多匹配不授业务权限，停用/离职仅保留应有交接能力，禁止自动猜测或注册 |
| 限频与费用 | 挑战服务已有手机号/IP 限频；`authentication_rate_limit.py` 有 global→IP→identity 数据库限频，供应商调用有并发上限 | 本次未在认证实现中找到独立设备发送限频、可审计费用额度和余额告警闭环；需补设备可信来源、跨实例并发计数、额度占用及未知费用保留 |
| 状态与回执 | 当前发送失败/异常保守进入 uncertain；校验传输失败不消耗错误验证码次数，已有通用审计 | 明确拒绝、余额不足、限频、超时等需脱敏分类；本次未找到 `DypnsSmsVerifyReport` 接入。补认证回执与未知结果恢复，发送受理、送达、验证、身份匹配、会话建立分别留证 |

当前默认的验证码长度、有效期和频控数值只是已有代码值；实施时联合产品规则及官方接口
重新核定，不把可配置范围视为供应商承诺。发送请求摘要应包含实际参数和配置版本，
配置更换不能让旧挑战错误地使用新场景或签名继续验证。

8.20 已落实当前供应商实例配置与原发送摘要绑定，覆盖实际发送及校验前的漂移拒绝；非 `provider_managed` 的历史挑战在验证、完成、消费及回放入口均拒绝成为新 PNVS 会话授权。158 项聚焦和 9 个真实本地 PG16 场景通过，无新迁移。此前“先等待 7.73 回归”的历史动作不再适用；当前完整门禁由最新交接记录统筹。凭据链、费用、设备限频、可信回执及真实联调不因此关闭。

| PNVS-01-F | 灰度启用、监控及可回退切换：小范围身份、额度/错误率/延迟/回执积压告警、停发演练 | 有完整验收及上线授权；停止新挑战后按原配置处理存量或安全失效，保留审计/幂等记录，不自动重发、不覆盖历史事实 |

RAM 策略先评估仅允许 `dypns:SendSmsVerifyCode`、`dypns:CheckSmsVerifyCode` 的身份；两 API
当前文档标注不支持资源级授权，不能虚构可限定的资源 ARN。回执订阅等额外权限单独核定，
不默认授予产品全权限。生产优先使用云角色/短期凭证，AK 路径如保留须有安全注入与轮换验收。

未知结果策略须在 A 阶段形成可实现的决策表：

1. 发送前持久化挑战、独占投递权和参数摘要；超时留 uncertain，原请求回查不再产生付费发送。
2. 同一准确挑战收到可信结果后追加恢复事实；没有供应商证明时保留未知，不凭时间经过判为未发送。
3. 费用额度先保守占用；未知发送不能立即释放额度。明确最终结果与账单/回执再按策略结算。
4. `UNKNOWN` 核验结果按明确失败处理；传输/结构异常不得冒充用户输错。一次性消费、本地会话与审计
   保持事务一致；供应商成功但本地失败的重入条件须有独立设计和并发证明。
5. 回执按当前官方机制验签/鉴权，绑定准确挑战、OutId 和供应商引用，拒绝重放/错配；仅改变认证事实。

## 5. 外部依赖与通知工作衔接

以下均登记为**待准备/待核验**：阿里云实名认证及 PNVS 开通状态、RAM/云角色权限和服务端
凭证注入、配套预置签名与模板编号、PNVS 套餐/余额及费用上限、指定测试号码和真实发送安排。

脱敏、审计和回执防重放基础设施，但认证挑战与业务通知不能共用可混淆的状态和消费规则。
