## 本批实现与开放边界

0145 在 PostgreSQL 中用完整报损证明替换 0142 的无条件写入拒绝。只有具备当前
明确权限、本人个人仓、已复核期初、合法数量/SN、完整附件的申请，才能在同一事务内
冻结库存并保存单据、不可变流水、审计、状态事件、Outbox 和独立通知对象。
申请后冻结资产仍由原工程师保管；通知状态不代表业务完成或供应商送达。

数据库在 COMMIT 重新核验身份、权限、保管责任、来源历史和冻结范围。每笔报损
冻结份额及指定 SN 必须保留，普通库存释放不能挪用；原请求重放只回读已有事实。
退回业务仍使用原证明函数。新增函数为私有函数，API 无直接执行权，运行安全清单
核验准确函数体和触发器属性。空库可往返；已有报损历史时禁止降级。

未种入正式报损权限；提交 HTTP 路由、区域核实、总部五种处置、专用冲销、请求
封存/恢复和客户端仍未完成。SQLite 保留关闭写入的边界。不能启用半成品报损流程。
