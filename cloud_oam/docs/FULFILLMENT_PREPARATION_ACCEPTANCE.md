# 履约准备清单验收

本批为需求详情增加出库前的只读履约准备清单，基于 V1.0 已实现的分配、占用和释放事实。
开发分支为 `codex/production-readiness-gates`；迁移 head 仍为 `20260910_0070`。
这一步完成的是备料核对入口，实际拣货确认、出库单与出库过账仍需后续实现。

## 已实现的行为

- 需求详情中，已最终批准的明细可打开履约准备清单；展示原占用单、来源、物料、原占用数量、
  累计释放、仍占用数量、核验结果及该笔剩余 SN。
- 数量始终满足 `原占用 = 已释放 + 仍占用`。全部释放的原记录保留展示，核验数量为零。
- 先验证原占用与每次释放的不可变命令、流水、SN、审计链和状态事件，再检查当前余额和 SN 位置。
- 共享占用账户必须足以覆盖该账户所有需求的净占用，余额不足时阻塞，不把其他单据的份额
  分给当前需求。SN 必须仍在本笔占用账户、处于有效状态且符合相同物料及批次。
- 来源停用、共享账户不足或 SN 位置不符，显示具体阻塞原因；不返回可供核对的数量或 SN。
- 支持只看可核对实物、显示全部占用、展开 SN、刷新清单。刷新失败立即移除旧清单。
- 新读取按当前正式身份、需求范围和库存读取权限授权；历史证明使用原操作者的冻结坐标，
  新的合法读取不要求读者仍持有原释放身份。原释放命令恢复的身份和过账权限要求保持不变。
- 页面读取前后均核验身份、权限和需求详情；切换账号、需求版本变化或其他写入开始时丢弃
  迟到响应。存在结果不明的需求操作时，准备读取暂缓。

## 接口与证据边界

`GET /api/v1/material-requests/{id}/fulfillment-preparation?request_line_id={line_id}`

只返回当前授权来源，响应为 `no-store`；不提供同名 POST。读取无账号创建、库存过账、
审计追加、通知、需求版本或状态更新。最多 100 笔原占用、1,000 笔释放、1,000 个 SN，
超过范围拒绝整个读取，不返回截断结果。

尚未最终批准、出库已经开始、期初证据缺失、投影变化、需求版本变化、权限不足或历史证据
不完整时拒绝读取。读到的清单是核对快照，不是库存锁定凭证；未来拣货提交须在自己的事务中
重新锁定账本、需求、原占用、余额及 SN 并核验。
