# 拒收退回与需求补偿：实现接续边界

日期：2026-10-06。依据正式 V1 基线 1.7、1.8、3.5、3.7、3.11 与生产验收红线。本文件记录未完成的实现路径，不是上线或生产写入授权。

## 已有事实与本次修复

本人验收保存原 `ReceiptLine.condition`、合格/拒收数量及逐件 `ReceiptSerial.accepted`。`material_request_my_receipt._result` 核对原命令、验收时间、明细和审计。拒收不触发个人仓入账，原物资仍在出库形成的在途账户。

此前 `my-inbounds/candidates` 仅返回合格 SN。本次在同一受本人身份约束的只读投影中补充原验收条件、验收时点有效的追踪规则和拒收 SN；PC/H5、小程序同步严格校验并分别展示。规则缺失、数量/SN不符或原证据不完整时，仅阻断该条验收，不返回未经验证的明细。没有新增退回写入口或库存交易。

## 不能直接复用的部分

- `stock_operation_orders` 的现有退回来源绑定工单拆回件或总部批准报损；它从个人仓库存出发。拒收物资从未进入个人仓，不能补一笔虚假个人入账来满足旧入口。
- `OutboundPosting.source_stock_account_id` 是拣货账户；原可用来源需沿其 `reservation_id` 找 `StockReservation.source_stock_account_id`，不能将退回默认记回拣货状态。
- `material_request_remainder.partition` 将累计拒收全部列为 `rejected_unsettled_qty`。0171取消只接收已经释放占用、其他七阶段均为零的剩余量；退回实物完成后也不能直接改旧拒收数量或旧取消证据来结单。

## 下一次完整写闭环

1. 用原验收、原验收行、原发运行、原出库、原占用和逐件拒收 SN 唯一绑定退回来源；每次只允许处理尚未被其他退回占用的原拒收数量。错误或缺失关联停止该对象。
2. 申请/退回实物发出、承运交接、来源仓实际验收和仓库入账分别保存事实。录入退回运单不能释放在途库存、取消需求或关闭业务单。
3. 来源仓验收由有该仓范围权限的区域负责人或总部管理员完成，重新核验身份、原关联、数量与 SN；工程师不得冒充来源仓接收。破损件应进入对应成色/隔离账户，不能自动恢复新件可用。
4. 来源仓独立入账从原在途账户转移，仅用统一库存过账入口，在同一事务中保存不可变业务单、库存流水、SN位置、审计和通知。错误物料/错误 SN 无法与原出库实物核对时保持异常，不凭照片猜测原 SN 已退回。
5. 退回入账是后续需求补偿的证据，不是取消本身。需增加独立的“已退回待补偿”数量阶段，保持逐行 `批准 = 入账 + 取消 + 所有未结阶段`；不得把已退回量伪装成从未分配过的可再次分配额度。
6. 原申请人确认补偿取消后，以前向迁移扩展取消核验和不可变证据，独立执行关闭。原审批、累计占用/释放/出库/验收与既有0171取消记录保持不变。历史读取要保留旧证据版本语义，不重写0171迁移。

### 退回补偿数量公式（待实现，不能直接改旧0171事实）

拆分取消来源：`取消总量 = 未履约取消量 + 已退回补偿取消量`。来源仓独立真实过账后才累计`退回入账量`，必须满足`已退回补偿取消量 ≤ 退回入账量 ≤ 原拒收量`。

- `拒收待处理 = 原拒收量 − 退回入账量`。
- `已退回待补偿 = 退回入账量 − 已退回补偿取消量`。
- `未占用 = 批准量 − 未履约取消量 − 累计占用 + 累计释放`。这里不能使用取消总量，否则已发出后退回的补偿会把未占用算成负数。
- 其余拣货/出库/发运/验收阶段保持原因果差分；逐行仍验证`批准 = 已入个人仓 + 取消总量 + 八个未结阶段`，不能把退回变成新可分配额度。

验证应包含“批准2、正常入账1、拒收1、退回入账1、补偿取消1”以及一条拒收行分批退回的数量/SN场景；不能用更新旧占用、释放、出库或拒收投影来配平。取消和独立关闭必须重新核验真实仓库入账及原库存事务，登记、运单或接收照片均不足以成为补偿依据。
