## 实现与边界

- 主机先校验明确容量，检查备份目录可用空间，再执行专用 worker 的 `--preflight`。
  worker 在空的私有任务目录核验空间和专用 OSS 配置后退出，不生成输入文件、不访问
  OSS。随后才导出数据库和旧附件，最后执行完整 worker 及主机 SHA256 校验。
- 容量范围为 1 MiB～1 TiB，按 1,024 字节对齐；主机和 worker 一致拒绝无效参数。
  主机/worker 要求当前可用空间至少为容量的 8 倍，数据库暂存要求 3 倍，旧附件暂存
  要求 2 倍。**这是瞬时检查，不是磁盘空间预留，也不能保证其他进程不会占满磁盘。**
- 新 `capacity.sh` 在子 shell 中写入最多 2 KiB 的临时探针，测出本机 shell 的文件
  大小限制单位，仅接受 512 或 1,024 字节，未知单位直接拒绝。每次实际导出在独立
  子进程设置精确字节上限，父进程限制不变，探针退出清理。已在本机核实 1 MiB 正好
  成功、再多 1 字节失败，不能把 shell 数值直接当字节。
- 数据库在打开备份事务前完成空间检查；catalog 和 pg_dump 分别限额，两个文件均
  成功后才输出同快照 tar。旧附件改为受限暂存实际 tar.gz，成功后再输出。主机分别
  限制两个接收文件，任意步骤失败均不运行后续发布或过期清理，并删除本次暂存目录。
- Compose 候选片段增加 API 的备份辅助脚本只读挂载；独立 object-backup 仍只取得
  专用 OSS 环境，不连接数据库网络，不加载应用/数据库驱动。正式接入需整体切换
  导出协议、脚本、挂载和共用纯校验模块，不能单独替换其中一项。
