# 8.05 日终对账查询与区域权限

本批在指定工作树 `codex/notification-delivery-worker` 开发，保留所有旧改动。
依据正式 V1.0 的总部/区域报表范围与省级控制数左右对账要求，新增查询接口；
不生成库存交易，不把数值匹配解释为差异审核通过。

## 接口与事实边界

- `GET /api/v1/reconciliations/daily`：按业务日期、区域筛选，UUID 游标分页，每页最多 20 份。
- `GET /api/v1/reconciliations/daily/{cutoff_id}`：来源与本地截止时间、区域、账本游标、
  原始截止/比较摘要、仓库与计量范围、明细数量。
- `GET /api/v1/reconciliations/daily/{cutoff_id}/items`：仓库/SKU/成色与两侧数量、差值；
  使用明细序号分页，每页最多 100 行，游标不会在 10 万行处截断。
- `GET /api/v1/reconciliations/daily/{cutoff_id}/excluded-quantities`：独立读取不计入口径的库存状态数量。

返回 `Cache-Control: no-store`。拒绝重复/未知查询参数，权限不足或证据结构异常时不返回数据。
`comparison_status` 仅表示数量比较，`review_status=not_recorded` 表示目前没有日终审核记录。
本批未提供日终解释/审核写接口，也未接入网页操作入口。
历史结果可以在原来源或映射已撤销后读取；页面需展示原截止时间，不能当成实时库存。

## 数据库与鉴权

0131 在 0130 的不可变截止档案上新增 `daily_reconciliation_reports` 只读视图及
`(region_org_id, id)` 查询索引。视图只投影必要字段，不返回原始全国账本、账号快照、
会话、访问令牌时间证据、私有档案或请求幂等键。

视图由迁移账号拥有，API 与备份账号仅 SELECT；原始截止/映射档案仍不给 API 读取权限。
生产启动校验视图的精确定义摘要、列名/类型、所有者、屏障选项、ACL、列授权、规则和触发器。
API 根据当前有效正式角色和 `reconciliation.read` 权限在 SQL 中限制区域；返回前再次检查
会话和权限；PostgreSQL 必须使用 READ COMMITTED，拒绝让重复读取旧快照掩盖撤权。总部管理员可查询全国，区域负责人限授权区域，工程师与外部审批身份不得访问。

0131 降级只移除可重建视图和索引，保留截止、映射、库存和审计事实；继续降到 0129 时，
0130 原有“非空事实拒绝降级”规则保持有效。历史迁移未重写。
