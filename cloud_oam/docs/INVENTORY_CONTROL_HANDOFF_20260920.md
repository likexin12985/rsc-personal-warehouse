# PC 控制来源核查与签名交接（7.46）

依据正式 V1.0 基线继续 B1。本批在 7.45 认证运维入口之上增加私有 PC 核查页面和用途受限的
文件交接，不增加生产来源授权，不发布控制账，不取得期初启动资格。工作树仍在
`codex/notification-delivery-worker`，HEAD `f713999` 之后的现有修改全部保留，尚未提交或推送。

## 已实现的链路

1. `/xx` 内部后台增加“来源配置”，要求正式 admin 角色及 `inventory_control:authorize`。
   服务端再次验证活动总部全国权限、当前网页登录会话和准确授权版本。
2. 管理员导入准确配置请求，生成最长 5 分钟的核查包。API 只写签发审计，不查询私有控制表，
   不持有 owner 数据库连接，也不执行授权决定。
3. 受控 owner 命令核对请求签名、用途、完整命令、部署 ID、实际 authorization 审计链 ID、
   原签发审计与当前身份；生成包含来源、区域、版本、审核文件摘要及历史决定的核查回执。
4. PC 将回执交给 API 验签后展示。明确核对来源、版本和审核原文件后，才能签发 execute 包。
   execute 再次检查准确核查摘要，决定和执行审计原子保存；CLI 只有收到 COMMIT 确认才输出回执。
5. 回执丢失使用独立 status 包回读原命令。同键重放只能返回原决定；状态查询缺失不能作为盲目
   重试依据。新的有效登录可恢复历史结果，不覆盖原执行会话或旧授权版本证据。

页面只在签名回执通过服务端和客户端契约校验、且 `recorded=true` 时显示“配置决策已记录”。
文件下载、交接包签发、配置决定、控制账发布与期初启动分别展示；`projection_published=false`
与 `start_ready=false` 保持。页面不在 Storage 保存回执或凭据；人员/授权版本变化会清空状态，
丢弃迟到结果。授权包签发失败后保留原请求用于查询，不自动重放。

本切片是需要操作员传递文件的受控运维链路。自动传输队列、审核原文件在页面内的受控下载、
密钥轮换演练、真实角色/UAT 和完整配置台体验仍待补齐，不能称为全自动配置闭环。

## 密钥及运行边界

功能默认关闭。启用时部署身份是准确、非空 UUID；两端必须指向同一个实际数据库审计链。
API 与 owner 使用不同的 Ed25519 签名密钥，不传递 RSC JWT。签名包仅授权一个准确命令及用途，
不授予通用 owner 能力。签名包和回执应留在受保护的交接路径，不作为公开附件或仓库源码。

| 进程 | 所需设置 | 不允许的设置 |
| --- | --- | --- |
| API | `OAM_CONTROL_CONFIGURATION_HANDOFF_ENABLED`、`OAM_CONTROL_CONFIGURATION_DEPLOYMENT_ID`、`OAM_CONTROL_CONFIGURATION_API_PRIVATE_KEY`、`OAM_CONTROL_CONFIGURATION_OWNER_PUBLIC_KEY` | owner 私钥、owner DSN |
| owner CLI | 同一启用开关/部署 ID，`OAM_CONTROL_CONFIGURATION_OWNER_PRIVATE_KEY`、`OAM_CONTROL_CONFIGURATION_API_PUBLIC_KEY`，原专用数据库设置 | API 私钥 |

密钥为 32 字节的 64 位小写十六进制，来自受控部署设置；本文不提供可用于真实环境的测试密钥。
生产 API 启动会拒绝不完整或混用的签名配置；两端执行时也重复校验，禁止一个生产进程同时
持有两套私钥。未启用时接口返回安全的不可用结果。验证失败不回显上传内容、凭据或 SQL。

owner CLI 保留原 preview/apply/status 入口，新增 `--handoff-file`；该选项与 `--command-file`
互斥，不能附带 `--mode` 或 `--access-token-fd`。操作模式由签名请求决定，不要求导出登录凭据。
沿用精确数据库名、直接 `star_oam_migrator` 身份、PG16、head 0113 和事务超时预检；不自动迁移，
不重试未知提交。返回码 3 表示 COMMIT 结果未知，应生成并执行原结果查询包。
