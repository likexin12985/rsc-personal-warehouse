## 本批实现

新增 `POST /api/v1/stocktakes/opening/from-publication`。客户端只提交准确的发布批次 ID、
区域及盘点业务输入；来源、SyncRun、完整控制行、数量和原证据摘要均由服务器取得。
不存在控制行客户端注入、遗漏、混批或将未发布空批次当作零库存的兼容路径。
新建任务仍调用既有原子盘点服务，未把启动任务误作库存已经过账。

旧 `POST /api/v1/stocktakes/opening` 同样执行新准入，并逐行比较完整服务端批次。
新增 PostgreSQL 0125 迁移：一个受限的 JSON 执行能力、一个内部准入函数和一个内部
触发函数；新任务有 BEFORE INSERT 与延迟至 COMMIT 的两项 ALWAYS 守卫。无新表，
API 不获私表 SELECT；Edge、projector、backup 不获新执行能力。函数正文、所有者、
签名、固定 search_path、执行权限和触发器属性纳入迁移及生产启动校验。

准入按发布范围锁、控制来源绑定、来源/区域、证据文件、SKU 锁、物料绑定和主数据
顺序与发布者串行。锁等待后复核最新批次、原始采集时效、映射、原来源/目录授权和
采集授权区间的撤销、原证据文件、物料采集绑定/版本/策略；结束时再次检查最早截止。
新建任务提交前再验，证据失效整批回滚。原发布者会话是当时的发布证据，不要求其
会话在后续启动时仍有效；当前启动人的身份和区域权限继续独立验证。

新 `GET /api/v1/stocktakes/opening/start-result` 按当前用户、原请求编号、准确区域和
发布批次只读恢复。响应禁止缓存，重验原任务、范围、控制快照、初盘、状态事件、
审计链和 outbox；重复读取不一致则拒绝返回。`not_observed` 只说明尚未读到结果，
`automatic_retry_allowed=false` 明确禁止将它当作自动重发授权。

历史任务不触发新鲜度守卫；不改变 `control_snapshot_at = SyncRun.completed_at` 的
既有版本锚点，采集时间与发布有效期独立核查。只读恢复不取得账本、任务或审计头写锁。
SQLite 仍仅为非生产领域算法测试参考；按发布批次启动的接口明确要求 PostgreSQL，
不能用 SQLite 通过数替代 PostgreSQL 准入证据。
