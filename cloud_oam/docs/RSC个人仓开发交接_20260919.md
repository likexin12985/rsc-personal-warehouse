## 未关闭的正式基线缺口

### 通知缺口

- **N1 真实 adapter**：微信、短信、飞书真实发送、凭据/KMS 边界、provider 错误语义和测试环境发送证据尚未完成。
- **N2 provider callback**：没有可上线的 HTTP 回调入口、各 provider 验签、时间窗、nonce、密钥来源、provider event 去重和安全审计。不要先写一个通用 callback。
- **N3 飞书双向机器人**：没有查询、跳转、审批/库存命令的正式接口链；机器人不能直接改库存。
- **N4 通知覆盖矩阵**：通用 `inventory.transaction.*` Outbox 尚未完整映射到通知事件，盘点等路径不能自动宣称会通知。
- **N5 通知专用真库并发**：仍需 PostgreSQL 16 下的同键/异键重试、worker 竞争、审计失败回滚和 provider timeout unknown 测试。

### 非通知缺口

- **B1 控制投影**：当前只有离线一致性校验和四摘要契约；缺可信来源/目录审批、不可变采集封存、前向事实表、受控 publisher、RLS/ACL、原子幂等发布、批次选择和启动恢复。
- **B2 数据迁移**：组织、人员、SKU、历史单据、附件的数量/关键字段/附件校验和多轮演练未闭合。
- **B3 日终对账**：尚无连续至少 3 天的省级 OAM 控制数与本地明细差异解释证据。
- **B4 真实环境身份与渠道**：首管理员、真实人员映射、微信/短信/KMS/私有附件链缺完整验收记录。
- **B5 恢复能力**：缺 RPO≤5 分钟、RTO≤2 小时的 PITR/WAL 或等效恢复演练，以及库存/SN/审计核对。
- **B6 UAT/真机**：缺真实角色、设备、附件和关键 V1.0 场景的 UAT/真机证据。
- **B7 压测**：缺 500 用户规模的延迟、错误率、锁等待、队列积压、限流和告警报告。

1. 先冻结库存事件通知覆盖矩阵，明确事件白名单、收件人解析、原事务幂等键和已接线业务去重。

4. 为通知 worker 和 callback 补真 PostgreSQL 16 并发/中断测试，再接预生产 adapter。
5. 继续处理迁移、对账、恢复、UAT、压测和灰度上线证据；每一项都要记录准确提交、环境、结果和边界。
