## 实现与使用边界

新增 `inventory_control_authority.py`、不可变 `InventoryControlAuthorityDecision` 和 **0113**
前向迁移。准备数据内部一致与“该来源/目录版本获准使用”分别保存。来源授权指向准确的 0112
binding；目录授权指向准确 catalog ID/摘要及指定的来源授权；撤销必须指向原授权 ID/摘要。
不按名称猜测绑定，也不把客户端自填的目录标志当作审批结果。

写入需直接 schema owner 连接，以及重新加载、加锁验证的有效总部 FormalPrincipal：正式人员、
有效全国 admin 范围、当前授权版本、已验证且非未来时间的身份与 `inventory_control:authorize`
权限。迁移只为既有总部 admin 角色种子化该业务权限，不增加独立角色，也不授予 API、edge 或
现有 projector 访问新表的数据库权限。权限拒绝优先于允许，失效账号或过期上下文不能录入。

每条决策保存证据文件 ID/摘要及元数据快照、原因、有效期、原请求和幂等键、操作者权限快照、
完整内容摘要及独立 authorization 审计链引用。文件必须 available、非空且摘要精确相同。
时间从数据库取值；不允许倒填决策时间或以历史时钟给新发布放行。未来生效和到期停止均支持。

本批是授权领域服务与持久模型，**尚未接入正式配置页面或经认证的配置命令传递入口**。
没有通过“填写一个管理员 ID”建立可对外调用的授权接口。实际审核文件、来源范围和操作者
身份仍须通过正式入口和真实数据验收；合成文件元数据不是真实授权书。

## 重放、撤销与审计

- 同一操作者的同 key/request 与相同内容返回原决策，不再追加审计；同坐标不同内容拒绝。
- 同一准确对象的有效授权区间不能重叠。目录有效期不能越过它引用的来源授权范围。
- 撤销立即生效且只追加一次。来源撤销使其依赖目录失效；旧来源和目录决策保持可追溯，
  新来源授权之后必须明确授予新目录授权，不能静默恢复旧目录。
- 停用来源不阻止明确撤销。证据文件被隔离或变更会使当前授权解析失败关闭，原决定历史仍保留。
- `_prove` 重证原请求、准确版本、父子授权、有效期、摘要与完整审计链成员关系；过期、撤销或
  审批人后来变化不改写已经发生的原决定。
- 保存点内写入决策和审计，失败整组回滚。另修复 0112 本地 SQLite 的真实外层事务启动，
  验证调用方对成功保存执行 rollback 时也不残留准备事实或授权审计。

只读 `resolve_inventory_control_authority` 按实际当前时间返回来源/目录是否获授权、准确 grant
ID 和决策游标。它保留调用方待改证据及审计，不刷新覆盖，不提前 flush 无关 Outbox。
该结果是当前观察，**不是发布许可凭据**；后续 publisher 必须在自己的受控事务中锁定并重验
授权、可变来源/文件证据及实际发布时刻的有效期。

来源授权、采集认证、采集证明、正式发布和启动资格保持独立。即使授权齐备，结果仍为
`source_authenticated=false`、`capture_attested=false`、`projection_published=false`、
`start_ready=false`。0112 原准备接口的全部 False 保持原义。
