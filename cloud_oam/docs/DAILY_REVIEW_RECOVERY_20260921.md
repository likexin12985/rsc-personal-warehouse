# 日终审核原请求恢复与永久终结（8.11）

依据正式 V1.0；本批为本地候选，未提交、推送或部署。本批聚焦、原生 PG16 和期初流程均已终结通过，源码冻结结束；完整门禁和生产验收仍未完成。

## 功能与接口

未知结果不能通过重试一个新请求来解决。本批增加两个固定监督进程接口，继续使用现有当前 JWT、同源 HttpOnly Cookie、API 数据库角色和事务期限：

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/reconciliations/daily/{cutoff_id}/request-recovery` | 只凭原请求安全坐标查询：找到原回执、找到永久终结证明，或尚未观察到结果 |
| `POST /api/v1/reconciliations/daily/{cutoff_id}/request-seal` | 明确终结尚未执行的原请求；如原请求已提交，则返回原回执，不能抹去已发生的审核事实 |

正文包含当前 `expected_authorization_version` 和 `reference`。后者仅含 `cutoff_id`、`actor_person_id`、`original_authorization_version`、`original_review_version`、`operation`、`trace_request_id`。终结另需固定确认值 `permanently_prevent_original_daily_review_request`。不接收数据库地址、原正文、幂等键、附件地址或令牌字段。

输出协议为 `rsc.daily_review_recovery.v1`，`outcome` 为 `found`、`sealed` 或 `not_observed`；所有结果的 `automatic_retry_allowed` 均为 false。只有 `sealed` 才包含永久不执行证明，`not_observed` 不能释放待核验记录。当前权限、人员和区域重新校验；原授权版本与当前授权版本分开，允许当前有效权限恢复自己的旧请求。

## 数据库与权限

- 新增迁移 `20261113_0134`，父版本 `20261112_0133`，只增加 `daily_review_request_seals` 及相关约束；保留历史审核、库存和来源截止事实。
- 当前会话、人员权限、截止对象、绑定行及人员请求号使用一致锁顺序。SQL 自身也取得同一请求锁；不能绕过 Python 检查插入已经终结的原请求。
- 每个终结事实必须在原事务内有唯一且完整匹配的 authorization 审计。数据库在 INSERT 和 COMMIT 重查当前会话、人员、区域、权限、原坐标及审计绑定；COMMIT 前会话或授权到期必须整体回滚。
- API 对新表只有 SELECT/INSERT，备份角色只有 SELECT；不增加库存修改权限。四个私有函数、七个 ALWAYS 触发器、即时唯一索引和函数正文均纳入启动目录核验。
- API 与迁移所有者均不能 UPDATE、DELETE 或 TRUNCATE 已有终结事实。非空降级先拒绝，不删除正向回执或永久终结证明。

运行就绪函数当前摘要为 `090cd3d905100ecd35933a838af64000205c5e81cc257bf8e06215f445914ee3`；当前 HEAD、CLI、采集角色配置和权限清单同步到 0134。SQLite 只用于结构/聚焦验证，正式执行仍要求 PostgreSQL 16。

## 接续与上线边界

后端证明已完成，下一步为浏览器安全坐标持久化、跨标签对象锁和明确的“查询原提交结果 / 终结原请求”交互。持久记录不保存完整正文、令牌、签名 URL 或幂等键；刷新、换人、撤权、存储损坏和锁不可用都停止新写入。得到准确匹配的原回执或永久终结证明之后，才可清除对应记录。
