## 基线原文与适用边界

已完整核对 [正式 V1 基线](../../docs/RSC个人仓与物资运营扩展系统_正式生产版需求与架构设计_V1.0.md) 与试点冻结范围：

- §4.2：“WAF、HTTPS、KMS/密钥托管、安全组和最小权限数据库账号。”原文没有强制购买阿里云付费 KMS；**密钥托管、安全隔离与最小权限仍需证明**。当前 `aliyun_kms` 是已有实现约束，需要正向适配，不能只删检查。
- §4.2：“OSS 私有 Bucket，使用短时签名 URL，不公开业务附件。”本方案保留，不改为公开附件或随意本地下载地址。
- §3.2 包含 `mobile_encrypted`；登录验证码不保存明文。当前应用还加密认证幂等重放响应和需求联系人姓名/手机号。缩小用户数不降低其保护要求。
- §4.2 的两台 ECS、RDS HA、Redis 为正式生产推荐。本试点采用已确认的现有单机路径，不声称达到该完整生产拓扑或高可用能力。
- §5 的 RPO ≤5 分钟、RTO ≤2 小时以及 §6 的授权、演练、书面验收仍为开放门禁。若试点要另定目标，必须单独明确决定；本方案未自行放宽。

有限业务链仍是申请/提交→审批→最小分配/占用→后台人工履约/发运→本人收货→个人仓入账。拣货界面和已列后置功能保持 capability/角色隐藏；所有底层状态、历史迁移和出库依赖保留。SMS-only 登录不属于延期的业务通知渠道。

## 必须解决的具体适配

1. **密钥托管有真实协议变更。** 两组 registry 分别用于认证响应重放和联系人快照；当前 factory、envelope、pin gate、readiness 以及冻结 PG 触发器硬绑定 Aliyun。新 provider 使用新 envelope/registry 坐标和追加式 provider 绑定；新增前向迁移，旧 Aliyun 行与读取能力保留。OpenBao 解密不返回 Aliyun KeyVersionId，不能伪造。详见 [密钥托管审查](LOW_COST_KEY_CUSTODY_REVIEW_20261008.md)。
2. **运行身份不能靠一个 URI 配置凭空产生。** 轻量服务关联角色不证明实例应用身份；OIDC 路径依赖真实签名根和发行者，短 token 文件必须持续投影，SDK 的 STS 续期需实测。PNVS/KMS 默认链和 OSS 当前环境凭据提供器不同，OSS 需要单独可续期适配并限制签名有效期。详见 [运行身份方案](LOW_COST_RUNTIME_IDENTITY_20261008.md) 与 [复用 OpenBao 的具体端点和引导根](LOW_COST_KEY_CUSTODY_REVIEW_20261008.md#10-同一-openbao-能否复用为阿里云机器-oidc-issuer)。
3. **附件禁止覆盖依赖 Bucket 设置。** 当前代码使用 `x-oss-forbid-overwrite`。官方说明版本控制已启用或暂停时该头不生效；因此首发附件应使用从未启用版本控制的新私有 Bucket，并做真实二次 PUT 拒绝和摘要回读。不要直接给现有适配器打开版本控制后宣称安全。另做隔离备份。[PutObject 文档](https://help.aliyun.com/zh/oss/developer-reference/putobject)
4. **完整恢复包括密钥服务。** 只备份数据库和包装密文 registry 不足以恢复。恢复清单必须绑定数据库、附件、密钥服务一致性快照、历史 key 版本、部署摘要和独立解封材料；恢复后真实解密两个用途的新旧测试数据，再检查 pins 和业务权限。
