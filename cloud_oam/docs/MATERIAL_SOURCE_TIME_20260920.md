# 正式物料的未知来源时间（7.55）

OAM 备件采集契约明确没有真实来源更新时间，但此前 materials 列、目录 API 和双端解析器都
要求非空时间，直接接入会使整个正式物料目录报错。7.55 将真实未知时间作为显式 null 贯通
数据库、正式目录 API、Web 和保留的小程序业务代码，不以采集/同步/当前时刻补造来源时间。
它是正式物料接入的必要依赖，尚未实现不可变正式来源版本和物料投影生产链。

## 数据与接口

0118 前向迁移仅解除 `materials.source_updated_at` 非空约束，保留全部已知值及原业务引用。
不新增表、权限、运行角色或库存事实。head readiness 和 owner 配置/传输登记预检同步到 0118。
若存在任一未知来源时间，降级在加锁后拒绝，不能补时间、删除数据或改写事实来满足旧约束。

PostgreSQL 路径使用同一事务的表锁和 ALTER COLUMN；SQLite 仅用于本地验证，重建时保留
原表和引用表的触发器、索引及数据，并检查外键完整性。SQLite 连接必须在迁移事务前明确采用
foreign_keys OFF；迁移不会静默关闭它，避免重建被引用父表时触发级联删除。临时的
legacy_alter_table 设置在成功或异常时均恢复，故障注入验证整个表重建回滚。

正式目录 `/api/v1/materials` 返回 schema_version=`2.0`。字段仍必须存在，未知值明确为 null；
缺字段、空字符串、自由文本和无时区时间不是未知值。已知时间仍转换为 UTC 并正常展示。
物料状态、当前库存策略、访问权限、分页和 no-store 边界保持；未知时间不赋予数据新鲜或来源可信资格。

Web 和小程序读者同时支持严格的 1.0 已知时间，以及 2.0 已知/未知时间。旧 1.0 仍拒绝 null，
未知版本和错误字段仍拒绝。物料选择器显示“来源更新时间：未知”，选择后仍以准确物料 ID
构造需求，不把 null 转成当前时间或空字符串。已有盘点计数指纹原本支持 null，本批验证了
未知时间物料的实际盘点、封存和原结果恢复，库存流水不因此改变。

## 发布顺序

应先发布能读取 1.0/2.0 的客户端，再迁移 0118 和发布输出 2.0 的 API；最后才能启用未来的
真实物料投影。原客户端只接受 1.0，不能先向它切换 2.0 后假定可用。生产部署和真机验收
尚未执行，本段是待执行顺序。现有公开小程序只注册 knowledge 页，业务源文件仍排除出上传包。

主页公开查询、“星星后台管理”到 /xx、独立个人仓构建保持。真实飞书目录仍 pending/0 条；
开发产物验证通过不能代替公开目录 release 门禁或生产上线。
