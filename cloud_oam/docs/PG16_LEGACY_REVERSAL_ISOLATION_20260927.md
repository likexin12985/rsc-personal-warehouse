## 问题与修正

远端 PG16 run `36290034428` 的 runtime job `108538277237` 在约 42 分钟后失败。
`assert_reversal_migration_rejects_detached_history` 为测试 0097，尝试将当前完整业务
夹具库逐级降回历史版本；0126 正确拒绝删除已存在的期初授权证据，因此测试根本
没有执行到预期的 0097 历史反例。准确报错为：
`0126 downgrade blocked: opening authorization evidence must be retained`。

现在使用原 CI 已有的受限临时数据库分配/回收工具，另建独立数据库：

1. 完整升级到准确 0096，再升级 0097、空库降回 0096，验证历史迁移链和函数源指纹。
2. 在事务内分别构造原交易标记、反向交易标记、原交易绑定工单作业三类错误历史候选。
3. 调用实际 0097 升级函数，必须由准确的历史预检拒绝；其他数据库错误不能当作通过。
4. 回滚后逐表核验事实，以及函数源、owner/ACL/安全属性和触发器目录不变。
5. 释放连接并只清理本轮创建的隔离数据库；当前主夹具库存与函数目录保持不变。

错误候选是未提交的迁移输入，不宣称其本身构成合法库存过账。此前真实 API 角色的
完整工单交易、通用逆向拒绝、原始 SQL 逆向拒绝、成对替换单独冲销拒绝测试保持原样，
继续在当前 head 主夹具运行。没有跳过断言、关闭触发器、删除主库历史或改写生产迁移。
