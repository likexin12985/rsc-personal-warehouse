## 已实现的规则

- 复用完整证据验证和全量/增量重建，验证所有分页与摘要后才取最新状态。删除记录不再参与汇总，
  明确空库存输出空候选，不伪造某个 SKU 的零行。非目标区域行保留计数，不合并到目标区域。
- `qtyStock`、`qtyLock` 只接受非负整数或规范十进制字符串，最多 15 位整数、3 位小数。
  浮点数、布尔值、负数、指数、非有限值、前后空格、前导零和超过三位小数均阻断，不自动舍入。
  上限为 `999999999999999.999`；聚合也检查该上限。独立 Decimal 上下文避免调用者精度影响结果。
- `control_qty` 按原始 `qtyStock` 计算；保留 `qtyLock`，不减去锁定数量。锁定数量缺失、异常或
  大于库存也阻断。该输入语义仍须真实来源验收，本批没有声称验证 OAM 实际库存时点语义。
- SKU 精确匹配正式物料，外部对象必须属于本次来源、实体类型为 material、准确外部编码等于
  SKU 且未删除。正式物料须 active；当前有效策略必须唯一。名称、大小写近似、默认单位不参与匹配。
- 单位必须与正式物料基础单位完全相等，不猜单位别名，不引入未经批准的换算。数量与锁定量
  均检查当前策略的小数位及是否允许分数。物料、外部对象和策略来自数据库，不能由检查文件替代。
- 品相必须有显式的 `(materialStatus, materialStockType)` 规则，字符串 `"1"` 和整数 `1` 是
  不同来源值。规则不得重复或冲突；目标值仅 new、used、damaged、scrapped。没有默认 new。
- 正数 SN 库存需要单个有效 `snNo` 且数量等于 1；同一物料在目标区域不同位置重复出现同一 SN
  会阻断两行。输出只保留原始行摘要，不输出 SN。当前采集白名单没有已确认的批次字段，lot 和
  lot_and_serial 策略保留 `lot_semantics_unavailable`，不将来源引用号猜作批次号。
- 按区域、正式物料、品相确定性汇总，使用已有 `opening_control_projection_payload` 合同生成
  候选；保留全部来源业务键、原始行摘要、仓库/位置、原始来源更新时间及实际策略 ID。
  来源时间未知仍为 null。任一行失败时整批 `candidate_groups=[]`，禁止把部分合格行作为省级总量。

## 检查入口与证据边界

已有 owner 侧 `configure_inventory_control.py --inspection-file` 可选择附带：

```json
{
  "preparation_id": "11111111-1111-4111-8111-111111111111",
  "expected_authorization_version": 1,
  "normalization_rules": {
    "revision": "synthetic-review-v1",
    "conditions": [
      {"material_status": "synthetic-usable", "material_stock_type": "synthetic-stock", "condition_code": "new"}
    ]
  }
}
```

上述品相仅是合成示例，不能当成真实 OAM 字典。实际使用须由审核人提供准确来源值。
检查文件仍经大小、重复 JSON 键和字段白名单检查；凭据仍只用隐藏输入或继承 FD。
没有该可选字段时原 7.49 检查输出保持；显式 null 不作为正规化请求接受。

返回审核输入版本、规则摘要、数据库物料/策略观察及摘要、完整行结果、问题统计、候选组、
当前授权观察摘要和准备链摘要。`normalization_complete` 只代表这些输入的数量与匹配检查完成。
规则文件没有变成已批准映射，正式物料来源版本也没有在本批获得完整的同步/审计证明，因此：

- `normalization_rules_authorized=false`
- `master_source_evidence_verified=false`
- `trusted_key_lifecycle_verified=false`
- `projection_published=false`、`start_ready=false`

检查先重新执行当前授权链，不能靠调用方提供的布尔值跳过。完成时重读物料策略，检查等待期间
变化和到期，再检查授权观察有效期与网页登录会话。实际行共享锁持续到调用方回滚；这些锁没有
封闭策略范围的插入竞争，输出不能成为跨事务发布许可。CLI 始终 rollback，不 commit。
未来 publisher 必须具有独立权限与范围锁、批准的映射版本和主数据来源证明，并在实际发布事务
重新证明这些事实，不能直接消费当前审核 JSON 发布。
