## 本批实现

- `0144` 新增 `stock_loss_files`：真实文件 FK、单头/业务类型复合 FK、每个文件仅绑定一张报损单。
- 附件必须是该申请人、该权限版本、专用用途下完成上传的文件；冻结附件元数据摘要及单头附件清单。
- PostgreSQL 延迟到事务提交检查绑定；更新、删除和 TRUNCATE 均拒绝，保留附件历史时拒绝降级。
- API 仅获 SELECT/INSERT；私有检查函数不授予 API 或 PUBLIC 调用权。运行就绪指纹、权限清单和迁移 head 同步到 `20261123_0144`。
- 保留 `0142` 报损写入阻断，不种入报损正式权限，不开放报损提交 HTTP 路由。
- 应用提交候选复用统一过账服务，整批冻结、绑定附件、写审计和独立通知事件；相同请求回读原事实，失败整批回滚。它仍缺完整 PostgreSQL 整单证明、请求封存/恢复及后续业务闭环。

审查发现并修正附件协议错配：文件名、大小、内容 SHA 等由文件列和上传请求摘要绑定，
并不是 `metadata_jsonb` 中的独立同名字段。现在按既有规范重算 `request_sha256`；
没有扩展文件协议或降低原文件完整性检查。
