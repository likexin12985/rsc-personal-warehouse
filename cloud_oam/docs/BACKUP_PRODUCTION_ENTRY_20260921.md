## 已落地的行为

- [backup.sh](../scripts/backup.sh) 保留独立备份凭据、077 文件权限、gzip/tar/SHA256 校验、
  失败清理和单次原子改名。数据库导出现在调用受控入口，并显式传入配置的 `POSTGRES_DB`，
  避免误用容器创建时的默认数据库名。
- [deployment/backup](../deployment/backup/backup_database.sh) 使用现有 sh、psql、pg_dump，
  不要求数据库镜像安装 Python。原完整角色权限检查移入 `role.sql`，在持锁连接与快照
  连接分别复核，没有给角色增加权限，也没有关闭 RLS。
- 先以 READ COMMITTED 取得所有受支持目标表的 ACCESS SHARE NOWAIT 锁，再新建
  REPEATABLE READ 快照，复核准确关系集合与完整可读策略，最后共享快照导出。
  锁保留至导出结束；`pg_dump` 锁等待超时及两层 psql 的子命令失败均向外传递。
- 入口只接受最多 63 字符的 ASCII 字母、数字、下划线数据库名，以及单一本机 Unix
  socket。连接串、URI、多主机列表、TCP 地址等在调用数据库客户端前拒绝；清除可能
  改写连接上下文的服务、参数及 hostaddr 环境变量，固定备份角色及 PG16 客户端。
- [Docker Compose](../docker-compose.yml) 增加 `deployment/backup` 到 `/opt/rsc-backup`
  的只读挂载。部署时需要应用该挂载；本任务没有重建或运行生产服务。
- 0109 通知目标和 0127 对账事件测试现在分别核对各自历史权限清单；当前 0128 清单仍由
  独立当前门禁验证。新入口测试加入静态 CI，备份包装脚本的测试在独立临时目录运行，
  避免读取开发机真实 `.env`。
