# 期初实盘计数恢复验收清单

本清单遵循项目根目录 `AGENTS.md` 和 V1.0，不授权生产操作。
范围仅为期初/复盘的范围计数命令，不代表启动、复核、过账、对账或关闭自身已具备持久恢复。
用户界面中的“历史实盘已核验”不是审批、分配、占用、出库、发货、物流签收、OAM 收货、
RSC/个人仓履约入库、通知送达或对账完成的证明。

## 前置环境

- 自动化使用本地替身传输/存储和 GitHub disposable PostgreSQL 16；不连接 OAM、RSC、
  Workflow、飞书、真实短信或生产数据库。
- 真机验收另需用户批准的隔离 API、虚构人员和库存、专用微信开发/体验环境。
  缺少任何条件时记录“未验收”，不得改用生产账号或生产数据。
- 每份证据记录准确 Git SHA、测试命令、工具/客户端版本、结果和耗时。CI 只覆盖其工作流
  所列后端/边缘静态及 PostgreSQL 动态门禁，不能替代 Web、小程序或真机验收。

## 必须保持的协议

计数发送前持久保存最小非敏感坐标：版本、命令类型、任务、轮次/轮号、范围、人员、授权版本
和追踪号。不得持久保存原始幂等键、实盘正文、联系人、token、Cookie 或请求 hash。

每次新命令最多一个 POST，401 不得自动刷新并重发该计数。已经存在恢复记录时只能核验原请求；
不能因新表单不同、页面重启、查询超时或 `not_observed` 创建替代坐标。小程序的恢复 GET 禁用
自动认证刷新；PC GET 可以遵循原有身份刷新流程，但不得重新发送计数 POST。

清标必须同时证实：新鲜身份及权限、精确历史完成事实、当前任务投影、再次身份/权限复核、
页面仍有效、存储中的全部坐标与原标记相同。历史轮完成与当前新复盘轮 pending 可以同时成立。
首次直接 POST 的极窄预提交拒绝白名单是独立路径，任何后续 GET 错误都不得冒充该拒绝。

## 自动化回归矩阵

| 场景 | 验收结果 |
| --- | --- |
| 成功响应正常返回 | 历史完成及当前投影复核前不清标；仅一个计数 POST |
| POST 已提交但响应丢失 | GET 核验原追踪号；证明完整才清标，不再次 POST |
| 标记写入后、POST 前进程中断 | 重启仍保留标记；查无结果仍阻止新写，不推断未执行 |
| 初盘有已处置记录后开复盘 | 原初盘历史可确认；当前复盘仍 pending，普通详情合法且业务表不变 |
| 当前投影错轮、错范围或时间证据漂移 | 保留原记录，不推进当前任务，不发送补偿命令 |
| 查无记录、通用 4xx、503、超时 | 保留标记与可用草稿，不生成新请求坐标 |
| 首次直接 POST 精确预提交拒绝 | 再验身份/权限与页面后，只解除同一个精确标记 |
| 登录人员/授权版本变化或权限撤销 | 不展示其他人员恢复坐标、不继承旧草稿，不清标 |
| 隐藏/卸载页面、迟到扫描或查询 | 不把迟到结果应用到新页面、其他身份或下一轮草稿 |
| 损坏、缺失能力或不一致的存储回读 | 失败关闭，无内存替代通道，无自动重建标记 |
| 同任务双击/双页面与确认弹窗重叠 | PC 同源原生 Web Lock / 小程序服务上下文租约不排队创建第二个命令 |
| 存在待核验 count 时执行其他同任务写入 | 在实际写入口阻止；不能仅依赖按钮 disabled |
| 数量 0.001、最大 numeric(18,3)、SN 数量 1 | 合法边界可提交；零、越界、超精度、SN 多件和精确重复维度在分配坐标前拒绝 |

后端测试入口：`backend/tests/test_opening_count_command_status.py`、
`backend/tests/test_formal_opening_stocktake_read.py` 和 `backend/tests/test_postgresql16_release_gate.py`。
客户端入口为 `frontend/src/openingCount*.test.ts`、期初页面测试，以及
`miniprogram/tests/opening-count-*.test.js`、`formal-stocktake-pages.test.js` 和 `auth-request.test.js`。

## 真机/浏览器专项验收（尚未完成）

在获批的隔离环境依次执行：正常计数；人为丢失计数响应；立即强制关闭后重启；恢复后再查询；
切换测试账号；撤销测试权限；后台挂起再返回；同任务双页面；存储不可用；非整数数量输入。
每例记录预期与实际 POST 次数、公开追踪号、历史轮与当前轮状态、标记是否保留和库存/版本差异。
不得把自动化 wx 替身测试当作微信真机生命周期验证。

只保存脱敏结果，不导出认证请求、原始请求头或生产内容。浏览器 Web Locks/微信同步存储能力
不符合要求时必须停止计数；不得临时改成内存锁或删标记来“继续验收”。

## 未执行结果的处置边界

目前没有“确认未执行并永久封存原命令”的完整服务端协议。`not_observed` 只说明本次查询未
观察到确定事实，不证明以后没有迟到提交。不得按 TTL、多次查无结果、人工猜测或数据库删行解除。
也不得指导用户清浏览器数据、删除微信存储、重装客户端来绕过待核验屏障。

后续需以原 POST 共用的提交级串行化边界保存不可变未执行证明，并阻断迟到 POST 及直接 SQL
绕过；在该协议完成并通过并发真库验收前，此类情况保持阻塞并提交公开坐标给获准的技术人员
核查。标记丢失、设备切换和跨设备并发也不能由客户端局部锁单独解决。
