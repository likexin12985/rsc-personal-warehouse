# 8.06 日终差异解释与独立审核核心

本批实现独立的领域规则 `backend/app/daily_reconciliation/review_core.py`，沿用正式基线
的仓库/SKU/成色左右对账、独立审核、不可变历史和无库存调整要求。
**当前仍为待接入的后端核心：没有新增正式写接口、权限种子或数据库迁移。** 当前 HEAD
保持 0131，现有查询仍返回 `review_status=not_recorded`。不得把内存中审核通过视为数据库已审核。

## 规则与协议

- 开启审核明确绑定截止 ID、截止摘要、完整比较摘要与投影源摘要，使用稳定的通用运行/明细 ID。
- 区域负责人仅解释授权区域的差异；总部管理员独立审核。仅持有权限名不能绕过精确角色、
  范围、生效时间、拒绝项或受限账号状态。
- 每次解释最多 100 项，带整体版本和明细版本；匹配行、未知行、重复行、过期版本拒绝。
- 每项解释必须有文字与附件。附件实际可访问性由后续可信适配器核验；核心只接受服务器侧
  的可用状态、ID、摘要、大小和 MIME 观察，不接受客户端提供的“已验证”声明。
- 总部可指定明细退回补证；其他已解释项目保留。重新解释追加历史，不覆盖原解释。
- 审核要求所有差异已解释且退回项均重新提交，重新核对当前附件元数据。一个附件 ID 被不同
  解释引用为不同版本时拒绝，避免字典合并隐藏不一致。
- 解释过该份对账的人员不得审核，包括双角色、换用户标识或其解释后来被另一人替换的情况。
- 全匹配或全零覆盖也可明确登记审核；数值匹配与审核完成保持独立。
- 已审核历史不允许继续修改。新数量事实使用新的截止；冲销或库存更正仍走原业务单和库存流水。
- 每个命令绑定操作者、原请求 ID、独立幂等键、整体版本、前一事件摘要、来源摘要及发生时间。
  原请求恢复返回当时的回执，不用最新状态替代；历史附件后来失效不抹除过去的成功回执。
- 投影计划保留原外部量、本地量和差值。审核后仅将差异状态投影为 resolved、运行投影为 approved，
  不生成库存写入。未修改的明细保留原更新时间。

状态轴：`not_recorded → awaiting_explanations / pending_review → changes_requested / approved`。
数值比较始终另保留 `matched / differences`。这些内部状态将通过独立日终绑定表映射到正式
`reconciliation_runs`、`reconciliation_items`，不新增一套可写库存余额。

## 下一批数据库接入约束

当前两只通用投影触发器 `rsc_guard_reconciliation_run_projection_0026` 和
`rsc_guard_reconciliation_item_projection_0026` 只接受期初绑定。原生测试确认直接写入日终
投影仍被拒绝，不能通过删触发器、给 API 原始截止表 SELECT 或借用期初命令表来绕过。
下一迁移建议 0132，但此版本当前尚未创建：

1. 保留通用运行/明细表，新增日终运行绑定、不可变命令/事件及命令消费封口。
   截止 ID 和运行 ID 唯一绑定，命令 `(actor_user_id, idempotency_key)`、
   `(actor_user_id, request_id)` 全局唯一，`(run_id, target_version)` 唯一。
   核心的单运行历史不能替代数据库的跨运行幂等约束。
2. 锁顺序为当前会话与人员权限图、精确截止/运行、按 ID 排序的证据文件，最后审计头。
   首次运行不存在时使用只针对该截止的事务锁；不得用全局业务锁串行所有区域。
3. 新日终 SQL 校验器独立验证截止事实、来源摘要、数量、命令前后版本、角色/区域和附件；
   两只旧触发器只为已严格绑定的日终对象分派到新校验器，其他分支原样保留。
   历史迁移不修改；函数修改必须核对旧摘要、固定 search_path、所有者和精确 ACL。
4. 命令、通用投影、日终绑定、状态事件、审计及必要 Outbox 同一事务消费封口。
   延迟提交检查再次校验会话到期、权限时限、撤权和完整命令链；禁止孤立命令或只改投影。
   审计最终锁之后不得再获取业务锁。
5. `create_daily` 给总部/区域；`explain_daily` 仅区域；`approve_daily` 仅总部，兼顾退回补证。
   原 `reconciliation.read` 继续承担读取权限。生产矩阵由迁移添加，不运行时自建。
6. 原截止、解释和审核事件只追加。删除、TRUNCATE、伪造重算摘要、跨区域写、重复提交、
   并发解释/审核、文件撤销、过期会话、提交结果未知、非空降级均要在真实 PG16 验证。
7. 扩展 0131 只读视图/查询，返回实际解释与审核投影。新 HTTP 请求仅接受命令字段；
   不接收来源快照、数量、操作者、授权结论或附件观察。未知结果按原请求查询恢复，不能盲重试。
8. 接入前验证通用投影可由截止和不可变事件重建；用原期初实盘/过账/解释/审核场景回归两只
   旧守卫。更新精确安全目录、版本固定值、恢复操作说明和当前工件，不能把本批核心测试代替迁移门禁。
