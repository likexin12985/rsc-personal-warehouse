# 0052–0058 盘点证据链发布清单

本清单定义 `20260903_0052` 至 `20260905_0058` 的盘点证据链，以及不得回写历史迁移的
必需前向修复。它只描述预生产和生产发布边界，不授权连接或修改任何 OAM、RSC、Workflow、
飞书或生产环境。所有真实发布仍须经过变更审批、双人复核、备份恢复演练和 PostgreSQL 16
发布门禁。

GitHub PostgreSQL 16 release-gate run
[`33907501757`](https://github.com/likexin12985/rsc-personal-warehouse/actions/runs/33907501757)
已在一次性 disposable PostgreSQL 16 环境对 Git SHA
`20c29f724d46112d06fd1734091ecee90500d636` 成功执行。该记录只证明这个准确提交在该临时环境
通过门禁，不等于预生产验收、生产变更审批或生产放行，也不得替代备份恢复演练和隔离 UAT。

## 1. 不支持混合版本滚动

迁移链的职责必须分别保留：

- `0052` 为每个期初盘点范围完成事实增加不可变的原始请求文档 `request_jsonb` 和解析结果文档
  `request_resolution_jsonb`，并约束请求、观测、盘点行、序列号、复核、过账、对账和关闭之间
  的因果关系。
- `0053` 修复 `0052` 十五表共享延迟触发器的表分派；非 `stocktake_rounds` 记录不再解析轮次
  专属字段。它不改变业务状态、函数身份、ACL 或触发器绑定。
- `0054` 修复复盘建立后对已封印来源初盘轮执行历史复证的语义；当前轮继续禁止提前存在复盘
  范围分配，历史来源轮则允许观察由复盘图独立封印的后继分配。它保持 helper 的 OID、签名、
  所有者、ACL、六个调用方和触发器绑定。
- `0055` 修复非期初盘点启动 guard/validator 对审计序号的错误排序：由不存在的
  `audit_events.sequence_no` 改为规范的 `audit.stream_version, audit.id`。它只原位
  替换 `0047` 函数源，保持历史迁移、函数身份、权限和触发器绑定不变。
- `0056` 修复非期初初盘 assignment guard。`0021` 的共享轮次分配 helper 原本把 initial round
  错误限制为 `task_type = 'opening'`，导致合法非期初初盘的 count line、observation 或 scope
  completion 被拒绝；`0056` 原位修正该谓词并保持三个 SECURITY DEFINER 调用方及 ALWAYS
  trigger 的最小权限边界。
- `0057` 为非期初差异生成增加有界 owner-lock：从 inventory ledger head 开始，按 task、完整
  principal 集合、round、账户/主数据及任务内证据图的确定顺序锁定，覆盖回放所读的流水、移动、
  SN、端点账户、复核/过账、附件和文件，最多锁定 `100000` 行。它不给 API 增加表级写权限，
  只授予最小 helper 执行权限；同时在 PostgreSQL 和 SQLite 封印已提交轮次的盘点
  `document_attachments`，并拒绝非期初任务写入 `stocktake_control_snapshot_lines`。
- `0058` 修复非期初复核证明的终态兼容。最终通过的 review graph 不再只接受瞬时 `approved`，
  而是准确接受 `approved`、`posted` 和 `closed`，因此正式过账、关闭对账和最终关闭不会在延迟
  validator 提交时被误拒绝；函数 OID、所有者、ACL 和三个 deferred ALWAYS triggers 保持不变。

| 应用版本 | 数据库版本 | 结果 |
| --- | --- | --- |
| 旧应用 | `0051` | 仅代表升级前状态，不具备 `0052` 证据链 |
| 新应用 | `0051` | 写入会引用不存在的列，失败关闭 |
| 旧应用 | `0052`–`0058` | 无法生成新版必需证据或遵循新版锁序，盘点写入必须被拒绝 |
| 新应用 | `0052` | 共享触发器仍可能在非轮次记录上失败，不得停留 |
| 新应用 | `0053` | 有效复盘会在历史来源轮复证时被拒绝，不得停留 |
| 新应用 | `0054` | 非期初启动仍会引用错误审计列，不得停留 |
| 新应用 | `0055` | 非期初初盘 assignment guard 仍错误拒绝合法事实，不得停留 |
| 新应用 | `0056` | 差异完整回放尚无 owner-lock，附件/control snapshot 边界未封闭，不得停留 |
| 新应用 | `0057` | 非期初任务进入 `posted`/`closed` 后复核图会被误拒绝，不得停留 |
| 新应用 | `0058` | 当前唯一受支持组合；仍须完成本环境的全部正式放行条件 |

因此禁止边迁移边保留旧实例处理盘点写请求，也禁止先发布新客户端或新后端再迁移数据库。

## 2. 维护窗口顺序

1. 记录待发布 Git SHA、容器镜像摘要、当前 Alembic revision 和变更单号，确认只有一个
   Alembic head，且应用、迁移和安全清单来自同一准确提交。
2. 在 disposable PostgreSQL 16 和预生产分别通过完整 release gate，并完成从真实结构脱敏副本
   的升级、备份、恢复和失败重试演练；不得用 SQLite 或本地跳过项替代。
3. 阻断 PC、小程序、API、Worker 和运维脚本的全部盘点变更入口，至少覆盖开始、实盘、补盘、
   差异生成、复核、复盘、终结、过账、对账、附件和关闭。允许无关只读流量时，仍须确认它不会
   持有 `0052`–`0058` 锁定表的长事务。
4. 等待全部既有盘点写事务结束，确认没有旧应用实例、离线队列或重试任务仍可提交盘点写入。
5. 使用正式备份身份生成一致性备份并验证清单，记录恢复点。备份未完成或恢复演练未通过时停止。
6. 仅由迁移角色执行 `alembic upgrade 20260905_0058`，或在已确认唯一 head 后执行
   `alembic upgrade head`。迁移必须按 `0052 → 0053 → 0054 → 0055 → 0056 → 0057 → 0058`
   连续完成，不得把任何中间 revision 当作运行终点，也不得修改历史迁移后强行通过。
7. 任一历史事实无法唯一证明，或函数 hash、shape、所有者、ACL、search_path、调用方、trigger
   绑定、ALWAYS/deferred 属性、readiness 不符时，迁移必须整体失败。不得手工补猜、置空、删除
   业务行、关闭触发器或扩大 API 权限。
8. 复核数据库 revision 为 `20260905_0058`，并复核正式函数体哈希、触发器、延迟约束、所有者、
   最小 ACL 和 readiness 后，一次性替换全部后端实例为同一已验收镜像，不得保留旧实例参与流量。
9. 盘点写事务必须保持 PostgreSQL `READ COMMITTED`。不得通过会话参数绕过同轮次 SN 别名锁、
   `0057` ledger-head-first owner-lock、附件封印或 control snapshot guard。
10. 只读检查 `/api/health/live` 与 `/api/health/ready`，随后仅在预生产或获准的隔离验收范围执行
    期初和非期初的零库存、批次、序列号、未知物料观测、差异回放、区域/总部复核、过账、对账、
    关闭和篡改拒绝用例。健康检查成功不能替代业务验收。
11. 确认请求文档、解析文档、观测、盘点行、序列号、差异、附件、复核和过账集合可重放一致，
    并确认审批、分配、占用、出库、发货、物流签收、OAM 收货、RSC/个人仓入库、通知送达和
    对账同步仍是独立状态。
12. 解除盘点写入维护窗口，持续观察数据库约束拒绝、死锁、超时、审计链和 readiness。任何异常
    先重新读取准确事实，再决定前向修复或整库恢复，禁止盲目重试写入。

## 3. 回滚与逐级降级边界

所有 schema 降级都必须在盘点写入口已关闭、旧事务已排空、准确备份已验证后逐级执行；任何一级
失败关闭都必须停止，不能跳过 revision 或删除事实绕过门禁。

| 降级 | 必须失败关闭的事实边界 |
| --- | --- |
| `0058 → 0057` | 存在任一非期初 `posted` 或 `closed` 事实时拒绝；旧 validator 无法表达这些终态复核证明 |
| `0057 → 0056` | 任一非期初任务已有 round submission 或 difference-set completion 时拒绝；offline downgrade 因无法执行在线证据检查也必须拒绝 |
| `0056 → 0055` | 存在任一非期初 count line、count observation 或 scope completion 时拒绝；opening 事实可保留 |
| `0055 → 0054` | 存在任一 start completion，或非期初任务已有非 draft 状态、启动字段、freeze、snapshot、round、启动 state event/audit 等 legacy start graph 时拒绝 |
| `0054 → 0053` | 仅允许没有任何期初任务或保留期初证据的空历史；降级会重新引入有效复盘无法提交的缺陷 |
| `0053 → 0052` | 仅允许没有不可丢失 opening graph 的空历史 |
| `0052 → 0051` | 仅允许没有 `0052` 两份请求证据和期初盘点事实的空历史 |

- SQLite 的 `0055`、`0056`、`0058` 是显式 schema no-op；`0057` 包含附件封印和非期初 control
  snapshot trigger，降级仍须在线检查已封印事实；`0052` 的两份请求证据列仍不得丢失。SQLite
  不能证明 PostgreSQL 函数源、OID、调用方、锁、ACL 或降级安全，不得替代 PostgreSQL 16 演练。
- 一旦迁移回填了证据或新版应用提交了任何相关事实，不得通过清空列、删除盘点行、关闭触发器、
  修改函数、使用 replica 模式或强制 Alembic 降级来回滚。
- `0052`–`0058` 都属于不可改写的迁移历史。发现缺陷只能新增前向迁移，禁止把修复倒灌进旧迁移
  后伪装成原版本。
- 数据库尚未产生新事实但应用发布失败时，先保持盘点写入口关闭并逐级验证降级前置；只要任一级
  降级门禁拒绝，就采用前向修复。
- 必须回到迁移前状态时，只能在获批事故流程中停止全部写入，恢复迁移前的完整一致性备份，并
  同步恢复匹配的旧应用镜像。不得把单表恢复或部分 schema 降级称为回滚完成。

## 4. 放行证据

正式放行记录至少应包含：准确 Git SHA、镜像摘要、GitHub PostgreSQL 16 release-gate run、迁移
前后 revision、备份与恢复演练结果、函数体/ACL/trigger/readiness 校验结果、维护窗口起止时间、
实例清单、隔离 UAT 结果和双人复核人。任何一项缺失都只能记为“尚未放行”，不能用 disposable
门禁、本地测试、SQLite 测试或健康检查通过代替。
