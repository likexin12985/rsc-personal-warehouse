## 产品目标

RSC 物资管理不是星星 OAM 的皮肤替换版，而是一套独立的数据和业务系统。它按当前生产 OAM 的真实字段、状态和操作习惯复刻核心业务能力，并增加 OAM 当前缺少的人员维度能力：

- 每位已开通人员拥有独立个人仓视图。
- 人员可以提交个人物料需求，查看审批、派发、在途和收货全过程。
- 个人领用物料必须关联工单，消耗、回收和退回可追溯。
- PC 管理端与原生微信小程序共用同一套权限、数据和审计日志。

不复制星星 OAM 的源码、商标或受保护视觉资源。没有正式 OpenAPI 时，OAM 仅作为经授权的只读数据源；云端不保存 OAM Token、Cookie、密码或验证码，也不自动回写 OAM。

## 统一库存模型

库存唯一口径为：

```text
仓库位置 + 持有人 + 物料 + 物料状态
```

- 持有人为空：总部仓或网点公共库存。
- 持有人为具体人员：该人员的个人仓。
- 物料状态分别记录好件、旧件、坏件；每条库存再拆分现有、占用、在途和可用。
- 个人仓是同一库存账本的人员视图，不另建一套无法对账的库存表。

## OAM 核心模块复刻顺序

| 优先级 | 模块 | 复刻范围与验收口径 |
|---|---|---|
| P1 | 工单管理 | 列表筛选、工单摘要、设备/场站/客户/质保信息、执行人、状态流转、详情标签页和权限范围 |
| P1 | 动态工作项 | 按生产规则支持 `columnType=1/2/3/4/6/7/8`；兼容字符串、数组、数值、图片和附件；保存配置快照与执行结果 |
| P1 | 费用与报价单 | 物料费用、服务费、其他费用、签名；支付状态 `3/0/1/2/4/5` 与回款状态分开建模；生成完整审计时间线 |
| P1 | 工单与物资闭环 | 个人需求、领用、占用、消耗、回收、退回全部关联工单，禁止通过修改库存绕过业务单据 |
| P2 | 客户联络 | 联系记录、预约/下次联络时间、联络状态、附件和操作人 |
| P2 | 关联工单与评论 | 关联关系、评论、附件、操作日志和状态流转视图 |
| P2 | 设备与场站主数据 | 设备编号/SN、型号、品牌、场站、服务地址、质保和问题分类 |
| P3 | 报表与预警 | 响应时效、库存短缺、呆滞、未退坏件、超时工单和人员绩效；所有指标保留口径版本 |

## 已确认的生产契约

- 工作项接口外层 `model` 是数组，`model[0].result` 仍需二次 JSON 解析。
- `columnType=1` 的结果是字符串编码，不能按 JSON Boolean 处理。
- 单选结果为字符串，多选结果为字符串数组。
- 数字项读取 `max/min/step`，可选空值允许为 `null`。
- 图片与附件分别处理；附件是生产新增的 `columnType=8`。
- 报价单当前状态不能代替完整历史，时间线需聚合报价详情、操作日志、签名时间和支付时间。
- 调拨派发只形成在途；仓管或指定接收人必须核对实物并手动收货。

## 下一开发里程碑

1. 将已完成的 OAM 工单只读镜像扩展为 RSC 自有工单数据模型，并保留来源快照和字段版本。
2. 完成动态工作项配置器与手机执行页，支持本系统新建工单和现场填写全部 `columnType`。
3. 将个人需求、领用、占用、消耗和回收绑定 RSC 工单，并生成费用草稿。
4. 补齐客户联络、评论、签名和验收资料的自有写入流程。
5. 以上模块通过契约测试和真实样本对照后，再讨论任何获授权的 OAM 双向接口。
